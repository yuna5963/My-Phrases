## 1. 背景・目的

利用者はNotionのデータベース「🔠 フレーズ集」に、日常英語の**チャンク（語・型）と例文**、
日本語訳をほぼ毎日蓄積している。しかしNotionは情報を「貯める」用途には向くが、「反復練習する」用途には向かない。

本システムは、蓄積したチャンク資産（1チャンク + 例文最大5 + メタ情報）を取り込み、
スマートフォンで手軽に
**今日の練習**（SRSの期日カードを習熟度に応じた形式で自動出題）・
**瞬間英作文**（日本語→英語を即座に生成し、チャンク→5例文を逐次で答え合わせ）・
**文脈穴埋め**（例文中のチャンクを伏せ字にして想起）・
**長文音読**（長文のお手本再生→続けて音読）・
**連続再生 / 再現練習**（チャンク→5例文を数珠つなぎで流し聞き／日本語を聞いてタッチで答え合わせ）・
**チャット練習**（AI英語コーチとの英会話で、覚えたチャンクを実際に使う）を
行えるようにすることを目的とする。チャンクは Type / Category / Level / Priority のメタ情報で
一覧・再生を絞り込める。

### ゴール
- 通勤・隙間時間にスマホで反復練習ができる
- Notionの蓄積を最小手間でアプリに反映できる
- 学習の進捗が記録され、復習すべきフレーズが自動で提示される
- 手を使えない場面でもフレーズを連続で流し聞きできる
- 覚えたチャンクを「使う」練習（会話でのアウトプット）ができ、足りない表現の発見が Notion への蓄積につながる

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| チャンク | 学習単位。見出しの語・型（en）・日本語訳（ja）・例文最大5（en/ja のペア）・メタ情報を持つ。本書では旧称「フレーズ」と同義 |
| 例文 | チャンクに紐づく英文と、その日本語訳のペア（最大5）。`examples:{en,ja}[]` |
| メタ情報 | チャンクの分類: Type（Nuance/Pattern/Chunk/Connector/Phrase。特別値 **Long Reading** は長文音読モード専用）・Category・Level（Basic/Core/Advanced）・Priority（★）・Note |
| 瞬間英作文 | 日本語訳を見て英語を即座に生成する練習。チャンク→例文1〜5を逐次で「日本語→タッチ→英文」と答え合わせする |
| モデリング | チャンクと5例文を、お手本を聞きながら声に出して音読する練習。独立モードは廃止し「今日の練習」の新規カード向け形式として継続 |
| 長文音読 | `Type = Long Reading` の長文だけを対象に、本文のお手本音声を聞いて続けて音読する練習 |
| 音節カナ（シラブル音節カナ） | 英文の発音を、アメリカ英語ベースで音節ごとにカタカナ表記したもの。強勢は `*…*` で囲み太字表示。英文の下に小さく添える（記法は `docs/シラブル音節記法.md`） |
| 連続再生プレイヤー | 一覧から起動し、チャンク→例文1→…を自動で次々読み上げる流し聞き機能 |
| 再現練習 | 連続再生以外の通常時に、日本語訳を聞いて自分で英語を再現→タッチで英文を表示し答え合わせ→さらにタッチで次へ進む練習（日本語訳ON時。自動送りはしない） |
| 暗くして再生 | 連続再生中に画面を黒く覆い、誤タッチを無効化して聴くモード |
| 覚えた | チャンク単位の手動チェック（SRSの習得済みとは別の主観マーク） |
| 自信なし | 「覚えた」が未チェックのチャンクを指す絞り込み条件 |
| SRS | 間隔反復学習（Spaced Repetition System）。Leitnerボックス方式 |
| インポート | NotionエクスポートまたはCSVファイルをアプリに読み込むこと |
| サンプルデータ | 未インポート時に表示される初期内蔵データ |
| チャット練習 | AI英語コーチと英語チャットで会話し、対象チャンクを実際に使う練習（§4.18）。AIは Gemini API の OpenAI 互換エンドポイント（無料枠）を利用 |
| 対象チャンク | チャット練習の1セッションで「使うこと」を狙うチャンク（SRSの弱い順に2〜6個）。チップ表示され、発話で使えると点灯する |
| フォーカス | チャンク詳細・例文カードから起動したとき「今これを練習したい」と指定されたチャンク（と例文の場面）。会話の中心になる |
| 追加候補 | チャット終了時のまとめでAIが提案する、フレーズ集に未収載の基本表現（`➕ 英語 — 日本語訳` 形式） |
| 表現ストック | 追加候補のうちチェックした表現を端末内に日付付きで蓄積する置き場（§4.19）。数日分をPCへ渡して例文作成→Notion追加する運用の中継地点 |

## 4. 機能要件

### 4.1 取り込み・書き出し（インポート / エクスポート）
- FR-01: NotionエクスポートまたはCSVファイルをアプリのUIから取り込めること。
- FR-02: 取り込み対応形式は **`.csv`（直接）/ `.zip`（Markdown & CSV一括）/ `.md`** とする。
- FR-03: `.zip` は解凍せずそのまま取り込めること（アプリ内で解凍）。
- FR-04: `.md` / `.csv` は複数ファイルの同時選択に対応すること。
- FR-05: 取り込んだデータは端末内に永続保存し、再起動・オフラインでも利用できること。
- FR-06: 再取り込みは**既定でマージ**とする（ID一致は上書き・アプリ内で追加した教材は保持・元データ側の削除は伝播しない）。**全置換**（削除を反映）もオプションとして選べること。いずれも学習進捗は保持すること。
- FR-06b: デッキ全件を**CSVでエクスポート（バックアップ）**でき、そのCSVを再取り込みすれば**ステータス・カナ含め完全に復元**できること。書き出しは、Web/PWA では OS の共有シート（メール・Drive 等）またはファイルダウンロード、**ネイティブアプリでは端末の公開 Documents フォルダへ直接保存**（Filesアプリ等から取り出せる）で行えること（C-18）。
- FR-07: 取り込みデータ（アプリ内追加分を含む）を消去し、サンプル表示に戻せること。消去前にバックアップを促すこと。
- FR-08: APIキーやサーバ連携、ターミナル操作を必須としないこと。
- FR-09: CSVは新フォーマット（`ID, Type, Category, Level, Priority, Chunk, 日本語, Example1, 日本語訳1, … Example5, 日本語訳5, Note`）に対応し、`Example{n}` と `日本語訳{n}` を例文ペアとして読み取ること。任意で音節カナ列（チャンク=`音節`、例文=`音節{n}`）と `ステータス`・`カナ要確認`（FR-179）列を読み取れること（FR-97〜101）。旧フォーマット（`フレーズ`/`日本語訳`/単一例文）も後方互換で読めること。

### 4.2 瞬間英作文
- FR-10: **「日本語訳を見て英作文 → タッチで答え合わせ」を、チャンク → 例文1 → … → 例文5 と1枚のカードで続けて練習**できること。
  各ステップは日本語訳のみ表示（＋読み上げ）→ タッチ → 英文＋カナ表示（＋読み上げ）→ タッチで次の項目へ。英文はタッチするまで非表示。自動では進まないこと。
- FR-11: 日本語訳のない例文は出題から除外すること（和訳は元データ側で用意する。C-08）。
- FR-12: 項目の進み（n / 総数）とチャンクのメタ情報（Type/Category/Level/Priority）をカード上に表示すること。
- FR-13: 最後の項目まで答え合わせしたら、自己採点を3段階（できた / あいまい / できなかった）で記録できること。
- FR-14: 「できた」以外はそのセッション内で再出題されること。
- FR-15: 出題キューは **Type → Category でまとめ直し**、次のチャンクへは同じタイプ・同じカテゴリのものへ優先的に遷移すること
  （グループはSRSの弱い順での初出順、グループ内も弱い順を保つ）。
- FR-16: 開示した英文は再生ボタン（🔊）で**何度でも聞き直せる**こと（押してもカードは進まない）。

### 4.3 モデリング練習【v0.6で削除】

  お手本を聞いて反復する「モデリング形式」は「今日の練習」（§4.13）の新規カード向けに継続する。
  なお「覚えた」チェックはチャンク一覧（FR-45）とチャンク詳細（FR-122）で引き続き操作できる。

### 4.5 長文音読
- FR-91: `Type` が **「Long Reading」** のフレーズのみを対象に、長文本文をお手本として提示・読み上げできること。
- FR-92: 本文（英文）をTTSで読み上げ・停止できること。読み上げ中は端末のスリープを抑止すること。
- FR-93: 本文の和訳を必要に応じて表示・非表示に切り替えられること。
- FR-94: 前後の長文へ手動で移動でき、移動・離脱時は読み上げを停止し和訳表示をリセットすること。
- FR-95: 対象（Long Reading）が0件のときは、その旨と取り込み方法の案内・AI長文作成（§4.21）への導線を表示すること。
- FR-96: 長文音読の対象（Long Reading）は、瞬間英作文・各一覧・ホームの集計からは除外すること。
- FR-96b: 長文音読の画面から AI長文作成（§4.21）へ移動できること。

### 4.6 連続再生プレイヤー / 再現練習
- FR-80: チャンク一覧／例文一覧でタップしたチャンクを起点に、一覧の並び順で「チャンク→例文1→…」を自動的に次々読み上げること。
- FR-81: 読み上げ項目（チャンク / 例文 / 日本語訳）を個別にON/OFFできること。
- FR-82: 日本語訳の読み上げ音声が端末に無い場合は、日本語訳の再生を無効化し理由を表示すること。
- FR-83: リピート（末尾で先頭へ戻る）/ シャッフル（ランダム順）を切り替えられること。
- FR-84: 前後のチャンクへ手動で移動できること。
- FR-85: 連続再生中は端末のスリープを抑止し、画面消灯で再生が止まらないようにすること。
- FR-86: **「暗くして再生」** モードで画面を黒く覆い、聴取中の誤タッチを無効化できること。
  解除は**2本指の同時タッチ**のみで行い、1本指タッチでは解除されないこと。再生停止で暗転も解除すること。

- FR-202: 【実験的】設定ONのとき、連続再生・長文音読の間ほぼ無音の音声をループ再生してブラウザの凍結を回避し、

### 4.16 読み上げハイライト（Word Spark）

### 4.20 教材化（表現ストック → AI補完 → デッキ追加）
- FR-176: 表現ストックの表現を選択し、AI が不足項目（**和訳・平易な例文1件・シラブル音節カナ・Type/Category/Level**）を補完した教材ドラフトを作成できること（「教材化する」ボタン）。

- FR-180: デッキへ追加できた表現は表現ストックから自動的に取り除くこと。
- FR-181: 生成の失敗・APIエラー時は成功済み分を保持し、失敗した項目だけ再生成・再試行できること。生成中は進捗を表示し、中止できること。

### 4.25 学習ログ・KPI・ゴール設定（学習の習慣化）
学習エンジン（練習機能）を日常の時間軸に載せ、「今日どれだけ進んだか」「最終ゴールにどれだけ近づいたか」を可視化して継続を支える。
- FR-220: 学習の**行動ログ**（いつ・どのモードで・何をしたか）を端末内に**追記型で記録**すること。記録対象は **採点・チャット完了・連続再生・教材化・意味ノード英語思考の完了**とし、記録の失敗が学習操作自体を妨げないこと（best-effort）。
- FR-221: 採点ログには採点前後の習熟度（Leitnerボックス）を含め、**「定着（box≧4）への昇格」を集計できる**こと。ログは全モード共通の採点窓口で一元記録すること。
- FR-222: チャット練習の**まとめ完了時**に、対象チャンク・**使えたチャンク**・送信数を記録すること（実戦投入率の材料。従来セッション終了で失われていた使用状況を永続化する）。
- FR-223: 連続再生・長文音読の**再生経過時間**を記録すること（長時間の画面オフ再生でも取りこぼしを抑えるため一定間隔＋停止時に記録し、ごく短い誤操作分は記録しない）。
- FR-224: ログから日次・週次のKPIを集計できること: 当日の**採点数・アウトプット数（採点＋チャット送信＋英語思考で組み立てた英文数）・定着昇格数**、当日の**最低ライン達成**（採点/チャット/英語思考が1件でもある、または連続再生が**5分以上**）、週次の**定着数・実戦投入率**。KPIの算出は純粋関数とし、表示するKPIは絞ること（数字疲れを避ける）。
- FR-225: **ゴール設定**を持つこと。最終ゴール（北極星）を **ビジネス／留学／日常会話** の**内蔵プリセット**から選び、各ゴールは**中間ゴールの梯子**（順に達成していく複数ステップ）を持つこと。中間ゴールの達成度は現状（SRS進捗）と学習ログから算出すること（例: **定着した構文カード数**・**起動レイテンシが基準内だった割合**・定着チャンク数・特定カテゴリの定着数・チャット実戦投入率・完了セッション数）。
- FR-225b: 梯子は**「構造優先」**とすること。学習のボトルネックはチャンクの「量」でなく構造の「自動化」であるため、**序盤の中間ゴールに構文の反射化（定着した構文カード数）と英語思考の起動速度（和訳→英文起動が基準時間内だった直近7日の割合。段階的にしきい値を縮める）を置き**、チャンクの「量」は土台として中盤に据えること（「量」から「速さ」への KPI 転換）。定着チャンク数の集計は、構文・意味ノード（Sentence Engine〈§4.27〉）と長文音読の教材を除いた**純チャンク**を対象とすること。
- FR-226: ホーム最上位に**ゴール進捗バー**を表示し、全体の達成率・**現在挑戦中の中間ゴール**（現在値／目標）・全ステップ一覧を確認でき、ゴールはいつでも選び直せること（§4.11 FR-65）。
- FR-227b: 【v1.6.0】ゴール枠の最下部に**「次のステップに進むには」**を表示すること。挑戦中の中間ゴールの指標ごとに、**どの練習を何回やれば進むか**を具体的な回数へ翻訳し（例「構文ドリルで『できた』をあと18回」「5秒以内の起動をあと7回」「チャット練習をあと4セッション」）、タップでそのモードへ直行できること。回数は現状の習熟度から実データで見積もること。〔`0/12` という表示だけでは次の行動が分からないため〕
- FR-227: 選択中のゴールと学習ログは端末内（IndexedDB）に保存し、フルバックアップ（FR-215）に含めること。中間ゴールの目標しきい値は後から調整可能な形で持つこと（実デッキの分布に合わせて較正する。**特定カテゴリを対象にする目標のしきい値は、そのカテゴリの実在チャンク数を超えないこと**＝到達不能を作らない）。

### 4.26 今日のプラン（Plan・当日メニューの提案）
「今日は何をどれだけやるか」をアプリが提案し、決断疲れ＝開始摩擦をなくす（学習OS化フェーズ1）。あくまで提案であり強制しない。
- FR-230: ホームに**「今日のプラン」**を持つこと。まず当日の**体調を3択**（疲れてる／普通／余裕あり）で選ばせ、選択に応じて今日やる候補アクションを**自動編成**すること。
- FR-231: 編成の方針は**構造優先**（§4.27。まず型の反射化から）とすること: **疲れてる**＝連続再生の流し聞きだけ（最低ライン到達で足りる）／**普通**＝構文ドリル→今日の練習／**余裕あり**＝構文ドリル→今日の練習→意味ノード生成→会話練習（チャットAPIキー未設定時は意味ノード生成までとする）。今日の期日到来数を文面に反映すること。
- FR-232: 各アクションはワンタップで該当モードへ遷移できること。**今日すでに実施済みのアクションは学習ログ（§4.25）から自動でチェック表示**すること（採点はモード別に判定し、今日の練習・瞬間英作文・構文ドリル・意味ノード生成を取り違えないこと）。
- FR-233: 選んだ体調・プランは**当日限り**で端末内に保存し、**日付が変われば未選択に戻す**こと（翌日はまた体調から）。強制はせず、いつでも選び直し・スキップができること。前日の結果に応じた初期値の自動反映（Act）は将来対応（§8）。

### 4.27 Sentence Engine（三層学習構造）
日本語で完成文を作ってから訳す癖を断ち、**チャンク→構文→意味ノード**の三層で「意味を見た瞬間に英語の骨格へ飛び込む反射」を鍛える（学習OS化フェーズ2）。
- FR-240: **構文ドリル**を持つこと。一つの構文パターン（例「XはYを意味する」）を常時提示しながら、その**変形例**を「日本語→声に出して英作文→タッチで答え合わせ」で連続反復できること。
- FR-241: **意味ノード生成**を持つこと。主張→根拠→補足のような**意味の骨子（複数ノード）**を提示し、**日本語の完成文を作らず**ノードごとに英文を組み立て、タッチで**参考出力**を確認できること（正解は一つに限らない旨を示す）。
- FR-242: 両モードは自己採点を3段階（§4.2 と同様）で記録でき、「できた」以外はそのセッション内で再出題されること。
- FR-243: 【v1.9.0 改訂】**起動レイテンシ**（意味の提示→**英語を言い始めるまで**の時間）を計測し、採点1回あたりの中央値を学習ログに記録すること。セッション完了画面に当日の中央値と**目安（5秒→3秒）**を表示すること。
  〔当初は「意味の提示→**英文開示（タップ）**まで」を測っていたが、これは**丁寧に言い直すほど値が悪化し、諦めて即開示すると良くなる**指標であり、速さの指標として機能していなかった。v1.9.0 で終点を発話開始に変更した。発話開始は音声モード（FR-252）でのみ取得できるため、声で答えていない間は計測不能として扱い、ゴール（FR-225b）では0件＝未計測とすること〕
- FR-248: 【v1.6.0】構文ドリル・意味ノード生成は**10問=1セット**のランダム出題とし、セットを終えたら**完了の演出**（達成の表示・正答率・全問正解の表示・「次のセットへ」）を出すこと。期日到来カードが1セット分に満たない日も**ランダムに補充して枚数を揃える**こと（達成の区切りを保つため）。セット中は「できた」以外の採点でカードを列末尾へ積み直さないこと（分母が練習中に増えると終わりが見えないため。弱いカードはSRSが当日再出題する）。**英文を一度でも開示すれば採点できる**こと（従来はカードの最後の例文まで開示しないと採点ボタンが出ず、途中で送ると離脱するしかなかった）。演出は `prefers-reduced-motion` を尊重し、同じ情報を静止画面でも伝えること。

### 4.28 検索の検証と較正（自己採点の甘さへの対処）
自己採点は**答えを見た後**にしか押せない構造だったため、後知恵バイアスで甘くなり、その甘さがSRSの出題間隔に複利で乗っていた。「思い出せた」と「知っていた」を分け、想起が実際に起きたことを確かめる（学習OS化フェーズ3）。
- FR-250: 【v1.7.0】**検索コミットゲート**を持つこと。英文の開示**前**に「◯ 言えた／△ あやしい」を申告させ、申告するまで開示できないこと。申告と開示は**1タップに統合**し操作回数を増やさないこと。設定でOFFにでき、OFF時は従来どおりタッチで開示すること（既定ON）。対象は再現練習・瞬間英作文・構文ドリル・意味ノード生成とすること。
- FR-251: 【v1.7.0】**較正メーター**を持つこと。「◯ 言えた」と申告して実際に「できた」だった割合と、「△ あやしい」と申告して「できた」だった割合を表示すること。前者が低ければ過信、100%に張り付くなら出題が容易すぎる、と読めること。**母数が少ないうち（10件未満）は割合を出さず件数のみ**を示すこと。文言は利用者を責めないものとすること（過信は一般的な傾向であり、責めると継続を損なうため）。
- FR-252: 【v1.9.0】**声で答えるドリル**を持つこと。設定でONにすると、開示前に**英語を声に出して答え**、認識結果を期待文と自動照合して ○一致／△一部／— の**参考表示**を出すこと。**照合結果を減点や強制不合格に使わないこと**（日本語なまりの誤認識で「言えたのに不正解」とするのは学習意欲を最も損なうため。採点の決定権は最後まで利用者に残す）。照合は完全一致ではなく**語の重なり率**で判定すること（認識が1語取りこぼしただけで不一致にしないため）。認識できた発話は証拠として学習ログに残すこと。マイク開始前に読み上げを停止すること（TTSの音を自分のマイクが拾うため）。音声認識に非対応の環境では FR-250 の申告ボタンへ自動的に戻ること。
- FR-253: 【v1.9.0】**甘さ指数**（自動照合が一致しなかったのに「できた」を付けた割合）を集計・表示できること。誤認識も混じるため断定に使わず傾向の材料にとどめる旨を添えること。

### 4.22 チャンク編集・手動追加
- FR-190: デッキ内のチャンクの**全フィールド**（英語・日本語訳・音節カナ・Type/Category/Level/Priority/ステータス/Note・例文最大5〈英・和・カナ〉）をアプリ内で編集できること。英語・日本語訳は必須とすること。
- FR-191: 編集で英語（Chunk）を変更しても、**IDと学習の記録（SRS進捗）・登録日時を維持**すること。
- FR-192: カナ欄は編集中にルールベース検証（FR-179）の結果を表示し、保存時に**「カナ要確認」フラグを再計算**すること（正しいカナに修正して保存すれば解除される）。
- FR-193: チャンクを**手動で新規追加**できること（一覧の「＋ 追加」から。既定値: Type=Chunk / Level=Core / ステータス=未着手）。追加分はアプリ内追加の教材としてマージ取り込み（FR-06）で保持されること。
- FR-194: 保存時に**同一英文の重複**（大文字小文字・記号差を正規化して比較）を検出し、重複時は保存せず既存チャンクへの導線を示すこと。編集時は自分自身を除いて判定すること。

## 5. 非機能要件

| 区分 | 要件 |
|---|---|
| NFR-01 オフライン | 初回読み込み後はネットワークなしで動作すること（PWA / Service Worker）。**例外: AI機能（チャット練習〈§4.18〉・教材化〈§4.20〉・AI長文〈§4.21〉）はオンライン必須**（オフライン時はその旨を表示） |
| NFR-02 プライバシー | 学習データ・フレーズは端末内のみに保存し、外部送信しないこと。**例外: AI機能では会話文・対象チャンク・教材化対象の表現（英語・和訳）が Gemini API へ送信される**（利用者が明示的に開始した場合のみ） |
| NFR-03 セキュリティ | クライアントにNotion APIキー等の秘密情報を持たせないこと。**チャット練習の Gemini APIキーは利用者自身が入力するものとし、端末内（localStorage）にのみ保存、Google のエンドポイント以外へ送信しない**こと |
| NFR-04 操作性 | スマホ縦持ちでの片手操作を前提としたモバイルファーストUI。各練習画面の離脱導線（「✕ やめる」「← 一覧へ」）は親指で届く画面**下部**に配置し、上部ヘッダーはタイトルと進捗の表示に限ること |
| NFR-05 インストール性 | ホーム画面に追加でき、スタンドアロン表示で起動できること |
| NFR-06 保守性 | 機能領域（SRS/保存/TTS/取り込み/画面）を分離した構成とすること |
| NFR-07 互換性 | 進捗はフレーズIDをキーに保持し、再取り込みで失われないこと |
| NFR-08 API利用の節度 | AI生成は無料枠で運用できるよう抑制すること: 明示的なボタン起点のみ生成 / 不足項目のみ生成 / 複数件はバッチ / 例文は初期1件 / リトライは1回まで |
| NFR-09 AI通信の信頼性 | 無料枠の混雑等で散発する**一時的なサーバーエラー（5xx）は、バックオフを挟んで自動再試行**すること（最大2回・本文受信前のみ・中止可能）。**429（レート上限）は自動再試行しない**こと（上限消費を悪化させないため）。自動再試行で回復しない場合も、成功済みの結果を失わずに手動で再試行できること（FR-165・FR-181） |

## 6. 制約・前提

- C-01: 【v1.9.0 改訂】**発音そのものの採点**（発音の良し悪し・アクセントのスコアリング）は対象外。
  v1.9.0 で音声認識による**解答内容の自動照合**〈FR-252〉を導入したが、これは**加点のみの参考表示**であり、
  **SRSに反映される採点は最後まで利用者の自己申告**とする（認識精度が学習者の実力を決めない設計）。
- C-02: TTSの音声品質・声の種類は端末の対応に依存する。
- C-03: iOS Safariでは、TTSの初回再生にユーザー操作（ボタンタップ）が必要。
- C-04: Notionとのリアルタイム自動同期は行わない。更新は利用者による再エクスポート＆再インポートで反映する。
- C-05: CSVは `ID` 列をそのまま id に採用する。`ID` 列が無い旧データや `.md` のテーブルでは英文から生成した安定IDで代替する（`.md` ページはファイル名末尾のNotionページIDを使用）。
- C-08: 例文の日本語訳は元データ（Notion/CSV）側で用意し、`日本語訳{n}` 列として保持する。空欄の場合、再現練習や和訳読み上げではその項目の和訳がスキップされる。
- C-06: 【Web/PWA限定】**ブラウザのTTS（Web Speech API）は画面消灯・タブ非表示で再生が停止する仕様**であり、確実な回避策がない。
  Web版の連続再生は画面点灯（Screen Wake Lock）前提＋実験的キープアライブ（FR-202）。
  **確実な画面オフ再生はネイティブアプリ（§4.24）が提供**する。
- C-07: **「暗くして再生」はバックライト自体を消す機能ではない**（Webに明るさ制御APIが無い）。
  画面を黒く塗るのみで、有機ELでは実質消灯に近く、液晶では手動で明るさを下げると効果的。
- C-09: 読み上げハイライト（§4.16）の単語同期精度は端末依存。boundary イベントが発火しないエンジン
  （Android Chrome の Google TTS 等）では文字数×再生速度からの**推定**となり、実際の発音と多少ずれることがある。
- C-10: AI機能（チャット練習〈§4.18〉・教材化〈§4.20〉・AI長文〈§4.21〉）はネットワークと利用者自身の Gemini APIキーが必要。無料枠の**レート制限（429）**に達した場合は時間を置く必要がある。応答の品質・可用性・無料枠の条件は Google 側の提供状況に依存する。
- C-11: チャンク使用検出（FR-162）は正規化＋単語境界の一致のみで、**活用形は検出しない**（例: チャンク `come down with` に対し発話 `came down with` は不一致）。
- C-12: Gemma 系モデルには応答冒頭に内部思考タグ（`<thought>…</thought>`）を出力する・`system` ロールを拒否する等の癖があり、クライアント側で吸収する（表示・履歴送信前の除去、user メッセージへの前置リトライ）。
- C-13: AI生成（教材化・AI長文）の訳・例文・カナは**下書き品質**であり、誤りを含み得る。カナの機械検証（FR-179）は書式の検査であって発音的な正しさを保証しない。プレビューでの確認と、要確認フラグの定期監査を前提とする。
- C-14: Gemini API は**残クォータを取得するAPIを提供していない**。無料枠の残り表示（§4.23）は端末内カウントによる目安であり、AI Studio や他端末での消費・Google 側の上限変更は反映できない。
- C-15: 実験的バックグラウンド再生（FR-202）は、ブラウザが「音声を再生中のタブ」を凍結・タイマー抑制の
  対象外にする挙動に依存する**非公式のハック**であり、ブラウザの更新で無効化され得る。iOS Safari では効果がない。
  効かない端末では「暗くして再生」（FR-86）かネイティブアプリを使う。
- C-16: **Android WebView には speechSynthesis が存在しない**（Chromium は対応予定なし）。ネイティブアプリの
  読み上げはシステムTTS直結のアダプタ（FR-210）で実現しており、Web Speech API は使っていない。
- C-17: APKの**署名キーを紛失すると上書きインストールが不可能**になる（アンインストール＝端末データ消失が必要。
  フルバックアップ〈FR-215〉からの復元は可能）。鍵はリポジトリ外（`Documents/my-phrases-signing/`）で保管し、
  複製をクラウド等に保持する運用とする。ネイティブアプリの初回インストール時はデータが空であり、
  移行はフルバックアップで行う（APIキーのみ再入力）。
- C-18: **Capacitor WebView ではブラウザのダウンロード（`<a download>`）も Web Share（`navigator.share({files})`）も機能しない**ため、ネイティブアプリの CSV／フルバックアップ書き出しは Filesystem プラグインで**公開 Documents フォルダへ直接保存**する（FR-06b・FR-215）。Android 11+ は**アプリからダウンロードフォルダへ直接書き込めない**仕様のため、取り出し可能な公開領域として Documents を採用する（Filesアプリ→Documents）。Android 10 以前向けにストレージ権限を宣言する。
