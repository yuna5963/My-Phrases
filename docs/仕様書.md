## 1. システム構成

クライアント完結型のアプリ。**自前のサーバ・バックエンドを持たない**。配布形態は2つ:
**Web/PWA**（GitHub Pages、従来どおり）と **Androidネイティブアプリ**（Capacitor の WebView シェル、v1.0.0〜。
同一コードベースで、読み上げエンジンとバックグラウンド再生だけがプラットフォーム別実装〈§9 / §10〉）。
唯一の外部依存は AI 機能（チャット練習 §8.13・教材化 §8.15・AI長文作成 §8.16）で、ブラウザから Gemini API（OpenAI互換）を直接呼ぶ（キーは端末内。§13）。

```
[ブラウザ / PWA]
  ├─ UI（React + React Router(HashRouter)）
  ├─ 状態管理（Zustand: 設定 / デッキ / チャット / 表現ストック）
  ├─ ロジック（SRS / セッション / TTS(連続読み上げ・間) / インポート解析・CSV出力 / Wake Lock・キープアライブ / AIチャット・AI生成）
  └─ 永続化（IndexedDB: チャンク・進捗・メタ・学習ログ / localStorage: 設定・APIキー・表現ストック）
        ▲ │                                 │
        │ ▼ 取り込み（マージ）・書き出し      │ AI機能のみ（HTTPS・SSEストリーミング）
[CSV（直接）/ Notionエクスポート]      [Gemini API（OpenAI互換 chat/completions）]
```

### 1.1 技術スタック

| 領域 | 採用技術 |
|---|---|
| 言語 | TypeScript |
| UI | React 18 |
| ビルド | Vite 5 |
| ルーティング | react-router-dom（HashRouter） |
| スタイル | Tailwind CSS（darkMode: media） |
| 状態管理 | Zustand（設定はpersistでlocalStorage保存） |
| 永続化 | IndexedDB（idb ラッパ） |
| ZIP解凍 | fflate（ブラウザ内・オフライン） |
| 音声 | Web Speech API（SpeechSynthesis） |
| スリープ抑止 | Screen Wake Lock API（連続再生中のみ） |
| PWA | vite-plugin-pwa（Workbox / Service Worker） |
| AIチャット | Gemini API の OpenAI 互換エンドポイント（fetch + SSE、SDK不使用。§13） |

## 3. データモデル

### 3.1 型定義（`src/types.ts`）

```ts
interface Example {
  en: string          // 例文（英語）
  ja: string          // その日本語訳（空可）
  kana?: string       // シラブル音節カナ＋強勢（任意・CSVの「音節{n}」列。§8.9参照）
}

interface Phrase {
  id: string          // 安定キー（csv:ID列 / md:ページID / 旧:英文ハッシュ）
  en: string          // チャンク（見出しの語・型）
  ja: string          // チャンクの日本語訳
  kana?: string       // チャンク英語のシラブル音節カナ＋強勢（任意・CSVの「音節」列）
  examples: Example[] // 例文（最大5・各 en/ja/kana）。長文音読では本文を examples[0] に持つ
  type: string        // Nuance / Pattern / Chunk / Connector / Phrase / Long Reading（特別扱い）
  category: string    // Daily Status / Health / Work ...
  level: string       // Basic / Core / Advanced
  priority: string    // ★の数（例: ★★★★★）
  note: string        // 補足メモ（空可）
  status: string      // '未着手' | '進行中' | '完了'（新CSVに列が無い場合は '未着手'）
  createdTime: string // ISO日時（CSV由来は ''。アプリ内追加〈教材化・AI長文〉は追加時刻＝「アプリ内追加」の印）
  kanaWarnings?: string[] // カナ検証（kanaLint §13.8）の要確認フィールドラベル（例: ['音節','音節1']）。CSV「カナ要確認」列と往復
}

interface Progress {
  id: string
  box: number         // Leitnerボックス 0..5
  due: string         // 次回出題日 'YYYY-MM-DD'
  correct: number
  wrong: number
  lastSeen: string    // 最終学習日時 ISO（未学習は ''）
  learned: boolean    // 手動「覚えた」チェック（SRSの習得済みとは別）
}

type Grade = 'good' | 'vague' | 'bad'
```

### 3.2 永続化（IndexedDB: `my-phrases`, version 3）

| ストア | キー | 値 | 用途 |
|---|---|---|---|
| `phrases` | `id`（keyPath） | Phrase | 取り込んだチャンク（空=サンプル使用） |
| `progress` | `id`（keyPath） | Progress | 学習進捗（チャンクと独立に保持・`learned` を含む） |
| `meta` | 任意キー | 任意 | `streak`（連続日数）, `lastStudyDate`, `goalTrackId`（選択中ゴール） |
| `events` | `id`（keyPath）／`date` index | LearningEvent | **学習ログ（v3で追加・追記型）**。日次集計は `date` インデックスで範囲取得（§14） |

- v2→v3 の `upgrade` は**追加型**（`oldVersion < 3` で `events` ストア＋`date` インデックスを作るのみ）。既存の phrases/progress/meta は不変で、既存ユーザーもデータを保ったまま移行する。
- 設定（音声/速度/自動再生/出題数/対象ステータス/連続再生の各設定）は localStorage（キー: `my-phrases-settings`）。
- **進捗とチャンクは別ストア**。再インポートでチャンクを入れ替えても、同一IDの進捗（`learned` 含む）は維持される。
- **id 採番方式の変更（FNVハッシュ→CSVの `ID` 列）に伴い、旧データからの移行時は進捗キーが変わり一度リセットされる**点に注意（データ構造を再構成した新データセットのため）。

## 4. SRS仕様（`src/lib/srs.ts`）

Leitnerボックス方式。ボックス 0..5（`MAX_BOX = 5`）。

### 4.1 出題間隔（日）

| box | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| INTERVALS | 0 | 1 | 3 | 7 | 16 | 45 |

### 4.2 採点による遷移（`applyGrade`）

| 採点 | box変化 | 次回出題日（due） | 補足 |
|---|---|---|---|
| good（できた/言えた） | `min(box+1, 5)` | 今日 + INTERVALS[新box] | correct++ |
| vague（あいまい/もう一度） | 変更なし | 今日 + 1日 | 早期に再復習 |
| bad（できなかった） | 0 にリセット | 今日（= +0日） | wrong++ |

- `isDue(p)`: `p.due <= 今日`
- `isMastered(p)`: `box >= 5`
- `isNew(p)`: `lastSeen === ''`
- 「覚えた」（`learned`）は SRS とは独立した主観マークで、出題間隔の計算には影響しない。
- 日付は端末ローカル時刻基準の `YYYY-MM-DD`。

### 4.3 ストリーク（`useDeck.bumpStreak`）

- `lastStudyDate` が当日でなければ更新。前日に学習していれば `streak + 1`、そうでなければ `1` にリセット。
- 呼び出し経路は3つ: **採点時**（`grade`）と、**連続再生・チャット練習完了時**（`notePlayback` / `noteChatComplete` が当日の `minimumLineMet`＝採点/チャット完了 or 再生5分 を満たしたとき。共通ヘルパー `logAndMaybeStreak`。§14）。これにより「疲れた日は連続再生だけ」「短くてもチャットを1本完走」でもストリークが途切れない（要件 FR-33）。チャットは**まとめ完了＝1セッション**を単位とし、1メッセージ送っただけの離脱は数えない。

## 5. 出題・統計仕様（`src/lib/session.ts`）

### 5.1 今日の出題（`buildSession`）
1. 対象 = 設定の `includeStatuses` に合致し、`isDue` かつ `!isMastered` のフレーズ。
2. 並び順 = box昇順（弱いカード優先）→ due昇順。
3. 先頭から `sessionSize` 枚を採用。
4. `onlyUnsure` 指定時は `learned` 済みを除外する（旧・発音練習の「自信なし」絞り込み用オプション。発音練習削除後は現行画面から未使用だが `useSession` には残す）。
5. 0枚の場合は、対象ステータスのフレーズをシャッフルして `sessionSize` 枚（自由練習フォールバック、`useSession` 側）。
   ただし `useSession` に `noFallback: true` を指定した画面（今日の練習）ではこの補充を行わず、空のまま返す。
6. `clusterByFacet: true` 指定時（瞬間英作文）は、選ばれたキューを `clusterByTypeCategory` で **Type → Category** にまとめ直す
   （グループは弱い順での初出順、グループ内も弱い順を保持）。

### 5.1b 「今日の練習」の形式出し分け（`src/lib/dailyForm.ts` の `formFor`）

| 条件 | 形式 |
|---|---|
| 進捗なし or `isNew`（未学習） | `model`（モデリング） |
| box 0-1 | `repro`（再現練習） |
| box 4以上 かつ `hasCloze` | `cloze`（文脈穴埋め） |
| それ以外（box 2-3、または穴埋め不可） | `compose`（瞬間英作文） |

形式はカード表示のたびに最新の進捗から算出する（キューには id のみ保持）。そのため
採点で box が変化すると、同一セッション内の再出題（good 以外で末尾に再キュー）でも形式が追従する。

### 5.2 練習対象
- 旧「文数による振り分け（`text.ts`）」は廃止。瞬間英作文・文脈穴埋め・今日の練習は**全チャンク**を対象とし、絞り込みは一覧のファセット（Type/Category/Level/Priority）や「自信なし」で行う。ただし `Type === 'Long Reading'` のフレーズは長文音読モード専用とし、これらのモード・各一覧・ホーム集計からは除外する（`excludeLongReading`）。

### 5.3 統計（`computeStats`）

| 指標 | 定義 |
|---|---|
| due（今日の出題） | 対象かつ `isDue` かつ未習得 の件数 |
| newCount（新規） | `isNew` の件数 |
| mastered（習得済み） | `isMastered` の件数 |
| studiedToday（今日やった） | `lastSeen` の日付が当日 の件数 |
| total（登録） | 対象ステータスの総数 |

## 6. インポート・エクスポート仕様（`src/lib/import.ts` / `export.ts` / `share.ts`）

入口: `parsePhrasesFromFiles(files: File[]): Promise<Phrase[]>`

### 6.1 ファイル種別の処理

| 入力 | 処理 |
|---|---|
| `.csv` | `fromCsv`（RFC4180準拠の簡易パーサ）。新フォーマット推奨 |
| `.zip` | fflate `unzipSync` で解凍し、`.md/.markdown/.txt/.csv` エントリのみ処理 |
| `.md/.markdown/.txt` | テーブル形式を優先（`fromMarkdownTable`）、無ければページ形式（`fromMarkdownPage`） |

複数ファイル・複数エントリの結果は **IDで重複排除**（後勝ち）。チャンク英語（`Chunk`/`フレーズ`）と和訳（`日本語`/`日本語訳`）の両方が空の行は除外。先頭セルのBOMは `trim()` で除去。

### 6.2 列・プロパティのマッピング

新CSVヘッダー契約（`音節` 系・`ステータス`・`カナ要確認` は任意。推奨は英・和の直後に音節を置く並び）:
```
ID,Type,Category,Level,Priority,Chunk,日本語,音節,Example1,日本語訳1,音節1,…,Example5,日本語訳5,音節5,Note,ステータス,カナ要確認
```

| Phrase | 新CSV列 | 旧Notion列（後方互換） |
|---|---|---|
| id | `ID` | （無ければ英文ハッシュ / MDはページID） |
| en | `Chunk` | `フレーズ`（CSVヘッダ / MD H1） |
| ja | `日本語` | `日本語訳` |
| kana | `音節`（任意。別名 `Chunk_Kana`/`Syllable` 等） | （無ければ空） |
| examples[n] | `Example{n}` + `日本語訳{n}` + `音節{n}`（音節は任意） | 単一 `使用例（例文）` 等 → 和訳なし1件 |
| type/category/level/priority/note | `Type`/`Category`/`Level`/`Priority`/`Note` | （無ければ空） |
| status | `ステータス`（無ければ `未着手`） | 同左 |

- 例文は `Example1`〜（連番が途切れるまで）を走査し、各 `Example{n}` と対応する `日本語訳{n}`（別名 `Example{n}_JA` 等）をペアにする。`Example{n}` が空のペアは飛ばす。
- `音節` / `音節{n}`（別名 `Example{n}_Kana`/`カナ{n}` 等）はシラブル音節カナ＋強勢。空欄可（後方互換）。記法は §8.9 と `docs/シラブル音節記法.md` を参照。
- `カナ要確認` 列は `kanaWarnings` の `;` 連結（例: `音節;音節1`）。エクスポート（§6.6）との往復用で、無ければ undefined。

### 6.3 ID採番（`makePhrase` / `stableId` / `idFromFilename`）
- `ID` 列があればそのまま採用（例: `MP001`）。
- `.md`: ファイル名末尾の32桁hex（NotionページID）を使用。
- それ以外: 英文（チャンク）の FNV-1a 32bit ハッシュ → `p_<hex>`。
- アプリ内追加（教材化 §8.15）も同じ `stableId(en)` を使う＝同じ英文を後日 Notion 経由で取り込んでも同一IDに収束し、重複しない。AI長文（§8.16）のみ `stableId(タイトル + 本文先頭64字)`（タイトル衝突対策）。

### 6.4 保存（`useDeck.importFiles(files, mode?)`）
1. `parsePhrasesFromFiles` で解析。0件なら例外（UIにエラー表示）。
2. **既定はマージ**（§6.5）: `getAllPhrases()` → `mergePhrases(existing, parsed)` → `putPhrases`（clear しない upsert）。
   設定画面のチェックで**全置換**も選択可: `replacePhrases`（clear → 全件 put、単一トランザクション）。
3. `load()` を再実行し、`source = 'imported'` で画面更新。戻り値は `ImportSummary {mode, added, updated, kept, total}`（UIが「追加 x件・更新 y件（既存 z件は保持）」と表示）。

### 6.5 マージ規則（`mergePhrases(existing, incoming): MergeResult`）
- **ID一致は incoming で上書き**。ただし incoming の `createdTime` が空（CSV由来）なら既存値を温存（アプリ内追加時刻の保護）。
- `kanaWarnings`: incoming がカナ列（`音節` 系）を持ち込んだ場合は既存フラグを**破棄**（人手修正済みとみなす）。カナ列も `カナ要確認` 列も無ければ既存値を維持。incoming 側の `カナ要確認` があればそれを採用。
- **existing にしかない行（アプリ内で追加した教材・Notion側で削除された行）は保持**＝削除は伝播しない。削除を反映したいときは全置換を使う。
- 進捗（`progress` ストア）には触れない。IDが不変なら自動で保持される。

### 6.6 CSVエクスポート（`export.ts` / `share.ts`）
- `phrasesToCsv(phrases)`: §6.2 のヘッダー契約どおりの列順で**デッキ全件**を出力。`ステータス`・`カナ要確認` も含み、**このCSVを再インポートすれば完全に復元できる**（ラウンドトリップは `export.test.ts` で担保）。
  - `Example1〜5` は常に5枠出力（歯抜けを作ると `readExamples` の走査が止まるため）。
  - 先頭に BOM（Excel 文字化け対策。インポート側は `trim()` が除去）、改行 CRLF、RFC-4180 エスケープ（`csvEscape`）。
- `stockToCsv(items)`: 表現ストックを `Chunk,日本語,追加日` で出力（列名をインポータの別名に合わせ、これ自体も再取り込み可能）。
- `shareOrDownloadCsv(filename, csv)` / `shareOrDownloadText(filename, content, mime)`: 出力先はプラットフォームで分岐する。
  - **ネイティブアプリ（`isNativeApp`）**: `@capacitor/filesystem` を**動的import**（Webバンドルに Capacitor を混入させないため）し、`Directory.Documents` へ `writeFile`（UTF-8）で**公開 Documents フォルダに直接保存**する（Filesアプリ→Documents から取り出せる）。Capacitor WebView では `<a download>` も `navigator.share({files})` も機能しないため（C-18）。Android 10 以前向けに `checkPermissions`→`requestPermissions` を試みる（11+ は不要）。成功で `'saved'`、失敗で `'failed'` を返す。
  - **Web/PWA**: `navigator.canShare({files})` が真なら **OSの共有シート**（メール・Drive 等）、不可なら `<a download>` ＋ `URL.createObjectURL` でダウンロード。共有シートのキャンセル（AbortError）はダウンロードへフォールバックしない。
  - 戻り値 `ShareOutcome = 'shared' | 'downloaded' | 'saved' | 'cancelled' | 'failed'`。呼び出し側（設定・表現ストック）は `saved`/`failed` に応じたメッセージを表示する。
- ファイル名: `my-phrases-deck-YYYYMMDD.csv` / `my-phrases-stock-YYYYMMDD.csv`。
- 導線: 設定「📤 デッキをCSVでバックアップ（n件）」（§8.8）、表現ストック「📤 CSVで共有 / 保存」（§8.14）。

| `setLearned(id, v)` | フレーズの「覚えた」状態を更新→`progress`ストア保存 |
| `importFiles(files, mode?)` | インポート（§6.4。既定マージ / 全置換）、`ImportSummary` を返す |
| `addPhrases(newPhrases)` | アプリ内で作った教材（教材化 §8.15・AI長文 §8.16・手動追加 §8.17）を `putPhrases` で追記 |

| `removePhrase(id)` | 教材1件を削除（チャンク詳細 §8.11）。`deletePhrase(id)` → `deleteProgress(id)`（SRS進捗も一緒に消す）→ `load()` |

**サンプル使用中（IndexedDBが空）の最初の書き込みでは、先に現在のデッキ全件を実体化**する
（差分だけ保存すると次の `load()` でサンプルが消えて見えるため）。以降 `source='imported'`。
| `reset()` | 進捗・ストリークを全消去 |

### 7.3 チャット（`src/store/useChat.ts`、非永続）

チャット練習のセッション状態。ストリーミング更新・中断をレンダリング外で扱うためストアに置くが、会話は揮発でよいので persist しない（タブ移動はグローバルストアが生きているため再開できる。アプリ再起動で消える）。

| 状態/アクション | 内容 |
|---|---|
| `targets` / `usedChunkIds` | 対象チャンクと、発話で使えたチャンクID |
| `messages` | 会話履歴 `{role, content, hidden?}`。`hidden` はキックオフ・まとめ依頼の内部ターン（表示しないが履歴として送る） |
| `status` / `error` | `'idle' \| 'streaming' \| 'error' \| 'done'`。エラー時も `messages` は保持 |
| `summary` / `suggestions` | まとめ本文と、➕ 追加候補（デッキ既存除外後。§13.4） |
| `startSession(targets, focus?)` | システムプロンプト構築→キックオフでコーチが先に挨拶。`focus`＝チャンク詳細/例文カード発の指定 |
| `sendUserMessage(text)` | 発話追加→`findUsedChunks` でチップ更新→ストリーミング応答。履歴は system＋直近20ターンを送信 |
| `retryLast()` / `requestSummary()` / `endSession()` | エラー後の再送 / まとめ取得（➕行のパース含む。**完了時に `useDeck.noteChatComplete` で1セッションを学習ログへ記録＝実戦投入率・ストリークの材料**。`usedChunkIds` は `endSession` で消えるため消える前に永続化する）/ 中断・全消去 |

- 古いストリームが新しいセッションへ書き込まないよう、実行ごとの `AbortController` の同一性で stale 判定して無視する。

### 7.4 表現ストック（`src/store/useStock.ts`、persist）

localStorage（キー: `my-phrases-stock`）。`items: {en, ja, addedAt(YYYY-MM-DD)}[]`。
追加は正規化キー（`chunkMatch.normalize`）で重複排除、`remove(en)` / `clear()`。§8.14 が表示・操作する。

### 8.4 長文音読（`LongReading.tsx`）
`Type === 'Long Reading'`（`isLongReading` / `LONG_READING_TYPE`）のフレーズのみを対象に、長文本文をお手本として読み上げ、続けて音読する練習。長文は本文・和訳を1つずつ持つ（`examples[0]` が本文。Example2 以降は空欄）。
- 対象は `phrases.filter(isLongReading)`。本文は `current.examples[0]`。`SessionHeader`（SRSキュー）は使わず、`pos`（0..n-1）でカードを送る独自の状態管理。
- ヘッダー（独自 `Header`）はタイトル「長文音読」と進捗（`pos+1 / total`）のみ。
- 本文領域だけを縦スクロール（`overflow-y-auto`）させ、「🔊お手本を聞く」ボタンは常時見える位置に固定。
- 「🔊お手本を聞く / ⏸停止」: 本文（英文）を `speak` で1回読み上げ（`onEnd`/`onError` で停止状態へ戻す）。再生中は `useWakeLock` で画面スリープを抑止。
- 設定 `bgPlayback` ON なら、お手本開始のタップ内でキープアライブを開始（§10.1。停止・カード切替・離脱で解除）。
- 読み上げ中は本文の**現在の単語を Word Spark ハイライト**（§9.1 の `SpokenText` + `useSpokenWordTracker`）。停止・終了・カード送りで消灯。
- 「訳を見る / 訳を隠す」で和訳（`examples[0].ja`）をトグル表示。カード送り（`pos` 変更）・離脱時は読み上げ停止・訳表示リセット。
- カード送りは共通 `StepNav`（← 戻る / 進む →）。片手操作のため「✕ やめる」は画面**最下部**（`StepNav` の下）に配置。
- 対象が0件のときは取り込み案内（「Type が『Long Reading』のフレーズを取り込むと表示」）と「＋ AIで長文を作る」「ホームへ戻る」を表示。
- 長文音読の対象（`Long Reading`）は瞬間英作文・各一覧・ホーム集計からは除外される（`excludeLongReading`）。
- ヘッダー右に「＋ AIで作る」→ AI長文作成（`/long-reading/new`、§8.16）への導線。

### 8.5 チャンク一覧（`Browse.tsx`）

- 検索（チャンク英語 / 日本語 / 例文の英・和の部分一致）、件数表示。
- 絞り込み: 「⚠️自信なし」トグルと、**Type / Category / Level / Priority のファセット行**（値はデータから動的生成、各ファセット1値選択・横断AND）。検索と絞り込みは共通フック `usePhraseFilter` ＋ 共通UI `FacetFilters` を例文一覧と共有する。
- 各項目: チャンク英語・日本語・習得済みマーク（✅）・「☐/☑覚えた」トグル・単発TTS再生（🔊）・連続再生直行（▶）。
- 項目をタップで**チャンク詳細**（`/chunk/:id`、§8.11）へ、**▶ボタンで連続再生プレイヤー**（`/phrase/:id`）へ直接遷移する。

- 件数が多いため**ページング**（1ページ100件、共通 `Pager`）。フィルタ変更時は先頭ページへ戻す。連続再生に渡す `ids` は**ページ内ではなく絞り込み結果全体**（ページをまたいで前後送りできる）。

### 8.6 例文一覧（`Examples.tsx`）
- チャンク一覧と**同一の上部フィルタ**（検索 / 自信なし / ファセット）を `usePhraseFilter` ＋ `FacetFilters` で流用。
- 絞り込み済みチャンクの例文1〜5を**平坦に展開**して一覧表示（英文＋**音節カナ**（`KanaLine`、設定 `showKana` ON かつ `Example.kana` 非空時）＋日本語訳。空の例文は除外）。出典として「例文N・チャンク英語」を併記。
- 件数が多いため**ページング**（1ページ100件、チャンク一覧と共通の `Pager`）。フィルタ変更時は先頭ページへ戻す。
- 各行をタップで**例文カード**（`/example/:phraseId/:index`、§8.6b）へ遷移（`location.state.items` ＝絞り込み結果の例文参照列 `{phraseId, index}[]`、`backTo` ＝ `/examples`）。各行に例文単体の単発TTS再生（🔊）。

### 8.6b 例文カード（`ExampleDetail.tsx`）
例文一覧でタップした例文を1枚のカードで練習する画面（下部ナビ非表示。`HIDDEN_PREFIXES` は `/examples` と衝突しないよう `'/example/'` で判定）。
- 共通 `ReproCard` に**例文1項目**を渡す＝瞬間英作文の例文表示と同一挙動（日本語→タッチ→英文＋カナ＋Word Spark ハイライト＋🔊もう一度）。
- ヘッダーに「例文カード n / 総数」、カード上部に出典（例文N・チャンク英語）。
- `StepNav` で `location.state.items`（絞り込み結果内の例文）を前後に移動（`key={pos}` でカードを初期化）。
- 「📚 チャンク詳細を見る →」で `/chunk/:id` へ（ids=items の重複除去チャンクID列、backTo 転送）。「💬 この例文で会話練習」で `/chat?focus=<phraseId>&example=<index>` へ（その例文の場面を中心にチャット練習。§8.13）。「← 一覧へ」は画面最下部。

### 8.7 連続再生プレイヤー / 再現練習（`PhraseDetail.tsx`）
チャンク一覧・例文一覧から起動し、単体表示・自動連続再生・再現練習を兼ねる。
- 再生順 `order`: `location.state.ids`（無ければ全チャンク）を基に構築。`shuffle` 時はタップ起点を先頭固定でシャッフル（`shuffleKeepingFirst`）。現在位置 `cursor+1 / order.length`。
- 「← 一覧へ」は `location.state.backTo`（既定 `/browse`）へ戻る＝起動元の一覧（チャンク/例文）に応じて遷移先を切替。片手操作のため画面**最下部**（← 戻る / 進む → の下）に配置し、上部ヘッダーはタイトルと進捗のみ。
- **項目（`buildItems`）**: チャンク（`speakPhrase`）→各例文（`speakExample`）。各項目は en/ja を持つ。
- **読み上げ列 `buildParts`**: 日本語訳ON（`speakJa`）なら各項目を **「和訳→英文」**、OFFなら英文のみで連結。
  **間（`SeqPart.gapAfter`）は 1項目内（和訳↔英文）=1.5秒、次の項目へ=2秒**（`GAP_EN_JA` / `GAP_NEXT`）。最後は間なし。
- **▶自動再生 / ⏸停止**: `speakSequence` で読み、1カード終了後さらに **2秒**空けて次のチャンクへ。末尾到達時は `repeat` ON なら先頭へ、OFFなら停止。
- 設定 `bgPlayback` ON なら、▶ / 🌙 のタップ内でキープアライブを開始し（§10.1）、カード送りごとに通知/ロック画面の表示（`updateKeepAliveMetadata`: 英文/和訳）を更新。停止（手動・末尾・エラー）と離脱で解除。
  再生中は▶の下に実験モードの作動状態（作動中 / 開始できませんでした）を小さく表示し、実機での切り分けに使う。
- **🌙暗くして再生（`DarkOverlay`）**: 全画面を黒く覆い、再生を継続したまま誤タッチを無効化。
  `onTouchStart` で `touches.length >= 2`（2本指同時）のときのみ解除、1本指は無効。再生停止で暗転も自動解除。
  ※バックライト自体はWebから消せないため見た目を黒くするのみ（§11参照）。
- **再現練習（reproActive = 停止中 かつ `speakJa` ON かつ 項目あり）**: カードを共通 `ReproCard` の単項目フォーカス表示に切替。
  「日本語訳のみ表示＋再生 → カードをタッチ → その項目の英文を表示＋再生 → **タッチで次項目の日本語訳へ**」。自動送りはしない。
  英文はタッチするまで非表示。項目送り・英文公開はどちらもカードのタッチ、チャンク間の移動は 戻る/進む。`ReproCard` 内のドライバ effect が音声を駆動する（瞬間英作文の「例文を見る」と同一実装）。
- 🔁リピート / 🔀シャッフル、読み上げ項目（🔊チャンク / 🔊例文 / 🇯🇵日本語訳）のトグル。
  日本語音声が端末に無い場合は日本語訳トグルを無効化し注記を表示（`hasVoiceForLang('ja')`）。
- ← 戻る / 進む →: 手動移動（停止中で `speakJa` OFF かつ `autoPlay` なら移動先を単発再生。`speakJa` ON時は再現練習ドライバが先頭から駆動）。
- 連続再生中・暗転中は `useWakeLock` で画面スリープを抑止。

### 8.8 設定（`Settings.tsx`）
- 音声: 読み上げ音声選択 / 再生速度（変更時にテスト発話・英語のみ適用）/ 自動読み上げ / **カナ（音節）を表示**（`showKana` トグル）。
- セッション: 出題枚数 / 対象ステータス。
- **チャット練習（AI）**: APIキー（password型・「端末内にのみ保存」を明記）/ **モデル（選択式）**: `Gemma 4（既定・無料枠が広め）` / `Gemini Flash（応答が速め）` / `その他（手入力）`（選ぶと入力欄を表示。プリセット外の保存値は「その他」として表示され温存。500混雑時の切り替え用途を注記）/ 解説を日本語にする / 対象チャンク数（2〜6）。**無料枠の残り目安**（`UsageBadge`、§13.9。集計の前提とリセット時刻の注記つき）。Google AI Studio（キー取得先）と表現ストック（件数つき、§8.14）へのリンク。

### 8.9 シラブル音節カナ表示（共通 `KanaLine.tsx`）
英文の発音学習補助として、英文の**下**に小さくシラブル音節カナを添える横断要素。`Phrase.kana` / `Example.kana`（CSVの `音節`/`音節{n}` 列）を表示する。
- 表示条件: 設定 `showKana` が ON **かつ** 当該 `kana` が非空のときのみ描画（空・未入力なら英文だけ）。
- 強勢: カナ文字列中の `*…*` で囲まれた部分を太字＋濃色（`font-semibold`・`text-slate-600`）で描画。`*` 自体は区切りとして消費し表示しない。
- 表示範囲: 瞬間英作文（`ReproCard` の開示英文）/ 今日の練習 / 文脈穴埋め / チャンク詳細 / 長文音読 / フレーズ再生（非再現カード・再現練習 `ReproCard`）**および例文一覧（`Examples.tsx` の各行、英文の下）**。**チャンク一覧の行は対象外**（一覧性維持）。
- 記法（`・`音節区切り / 半角空白=単語区切り / `‿`リンキング / `( )`脱落音 / `*…*`強勢）の詳細・作成手順・ChatGPT量産プロンプトは `docs/シラブル音節記法.md` に規定。

### 8.10 今日の練習（`Daily.tsx`）
SRSの期日到来カードを、習熟度に応じた練習形式で自動出題する統合セッション。
- セッション: `useSession({ noFallback: true })`。期日到来カードが0件のときは補充せず「今日の練習はすべて完了です 🎉」＋ホームへ戻る導線を表示（§5.1）。
- 形式の出し分けは `formFor(progress[id], phrase)`（§5.1b）。現在の形式（📝モデリング / 🔁再現練習 / ⚡瞬間英作文 / 🧩文脈穴埋め）を `SessionHeader` 直下にラベル表示。
- **model**: 共通 `ModelCard`（チャンク+カナ+和訳+メタ+例文、個別🔊）＋「🔊お手本を聞く / ⏸停止」トグル（`modelParts` を `speakSequence` 間2秒、トークンでカード切替時に中断）＋2段階採点（🔁もう一度=vague / ✅言えた=good）。`autoPlay` 時はカード表示で**チャンクのみ**自動再生。
- **repro**: 共通 `ReproCard` に**チャンク1項目**（en/ja/kana）を渡す。英文公開（`onStep` で検知）後に3段階採点 `GradeButtons` を表示。
- **compose**: 瞬間英作文（§8.2）と同じ逐次練習（`ReproCard` + `chunkAndExampleItems`: チャンク→例文1〜5）。最後の項目を開示したら `GradeButtons`。
- **cloze**: 共通 `ClozeCard`（§8.12 と同じ挙動）。開示後に `GradeButtons`。
- 採点は既存 `useSession.answer`（`useDeck.grade` → SRS）に統合。`good` 以外は末尾へ再キューされ、box の変化に応じて再出題時の形式も変わる。
- カード送りは `StepNav`、「✕ やめる」は画面最下部。カード切替・離脱時は読み上げを停止（トークン＋`stopSpeaking`）。

### 8.11 チャンク詳細（`ChunkDetail.tsx`）
チャンクの情報と学習の記録を確認する画面（下部ナビは表示したまま）。CSV相当の全項目（英・カナ・和・メタ・例文5・note・ステータス）がここで確認できる。
- 表示: 見出し右肩に**ステータス**、共通 `ModelCard`（英語+カナ+和訳+メタ+例文・個別🔊）、カナ要確認バナー（`kanaWarnings`。「✏️ 編集」でカナを修正すると解除される旨を案内）、note（あれば枠囲み）、学習の記録カード。
- 学習の記録: 習熟度 `box / 5`・「できた」（correct）・「できなかった」（wrong）・次回出題のひと言（未学習（新規）/ 今日出題 / 次回 YYYY-MM-DD / 習得済み✅）・「☐/☑覚えた」トグル（`setLearned`）。

- 対象IDが見つからないときはフォールバック表示（「フレーズが見つかりませんでした」＋一覧へ戻る）。削除直後の古いIDへの遷移もこれで吸収する。

### 8.12 文脈穴埋め【v1.8.0 で専用画面を削除・`Daily` に統合】
**`pages/Cloze.tsx` と `/cloze` ルートは v1.8.0 で削除**した。ホームのモードカードを外すとどこからも辿れない画面になるため（化石を残さない）。穴埋め自体は「今日の練習」（§8.10）の一形式として存続し、`components/ClozeCard.tsx` と `lib/cloze.ts` は `Daily` が使い続ける。以下は形式としての仕様。

例文中のチャンクを伏せ字にして、文脈と日本語ヒントからチャンクを想起する練習。
- マッチング（`findChunkSpan`）: 大文字小文字無視＋**単語境界チェック**の部分一致（`in` が `going` に一致しない）。アポストロフィの字種差（`'`/`’`）は正規化して吸収。**活用形の探索（ステミング）はしない**＝見つからない例文は対象外。
- 出題対象: `useSession({ filter: hasCloze })`＝マッチ例文を1つ以上持つフレーズのみ。**1チャンク=1問**とし、マッチ例文からランダムに1つ選ぶ（同一カード表示中は固定）。進捗がチャンク単位のため、複数例文の連続出題で box が不当に進むのを避ける。
- カード（`ClozeCard`）: 伏せ字（固定 `____`、強調色）入り英文＋例文和訳＋ヒント（チャンクの日本語）→「答えを見る」で全文（チャンク部分を強調）＋カナ＋再生ボタン。`autoPlay` なら開示時に例文全文を自動再生。
- 開示後に3段階採点（`GradeButtons`）。`good` 以外は末尾へ再投入。対象0件なら「穴埋めにできる例文がありません」を表示。
- 純関数（`findChunkSpan` / `maskChunk` / `clozeItems` / `hasCloze`）は `src/lib/cloze.test.ts` でユニットテスト（`npm test`、vitest）。

### 8.13 チャット練習（`ChatPractice.tsx` + `useChat`）
AI英語コーチとの英会話で対象チャンクを実際に使う練習（要件 §4.18。AI連携の詳細は §13）。
会話画面も他タブと同じ通常レイアウト（**下部ナビ表示**。v1.0.1で全画面をやめ統一）。
入力バーはナビの上に収まり、タブ移動してもセッションはストアに残るので会話・まとめは消えない。

- **対象チャンクの選定**: プール＝長文読解を除き対象ステータスに合致するチャンク。`buildSession`（期日到来・弱い順）を優先し、`chatTargetCount` 件に足りなければランダム補充。
  `?focus=<id>(&example=<n>)`（チャンク詳細 §8.11 / 例文カード §8.6b 発）があればそのチャンクを先頭に置き、システムプロンプトへ「今これを練習したい」（例文指定時はその場面を会話の中心に）と注入する。
- **セッション**: 開始時に非表示のキックオフターンを送り、**コーチが先に英語で挨拶**する。応答は SSE ストリーミングで最後のバブルへ逐次描画。
  マウント時、既存セッションがあり focus 指定が無ければ**進行中でもまとめ済みでも再開**する（他ページと行き来しても会話・まとめが消えない。まとめ済みならまとめ画面のまま）。新規開始は focus 指定時と「もう一度」（focus を引き継がず新しいチャンクで。クエリも除去）のみ。
- **チップ**: 対象チャンクを横スクロールのチップ表示。ユーザー送信ごとに `findUsedChunks`（`lib/chunkMatch.ts`: 小文字化・短縮形展開・記号除去の正規化＋単語境界一致。`...`/`〜` 等の穴あきチャンクは固定語のまとまりの順序出現で判定）で判定し、使えたチップを点灯（emerald＋✓）。活用形は不一致（既知の割り切り）。
- **入力**: textarea＋送信ボタン。Enter 送信は `e.nativeEvent.isComposing` ガードで日本語IMEの変換確定と区別。ストリーミング中は送信不可。
- **ソフトウェアキーボード対応**: viewport meta の `interactive-widget=resizes-content`（Web）/ WebViewのリサイズ（ネイティブ）でキーボード分だけレイアウトが縮み、入力バーが見えたまま。`visualViewport` の resize で最新メッセージまで自動スクロールし、AI側のトークが隠れない。
- チップの下に無料枠の残り目安（`UsageBadge`、§13.9）。
- **エラー**: `ChatApiError`（§13.3）を日本語で表示し、**会話履歴を保持したまま**「もう一度送る」（`retryLast`）で再送できる。APIキー未設定時は設定画面への導線、フレーズ0件時はホームへの導線。
- **終了→まとめ**: 「終了してまとめ」で非表示のまとめ依頼ターンを送り、日本語まとめ（使えたチャンク n/m・チップ・講評）を表示。まとめ本文から ➕ 行（追加候補）を分離し（§13.4）、**チェックボックス付きで表示**（チェック＝表現ストックへ追加、解除＝取り消し。§8.14）。
  共有: 「✉️ メールで共有」（mailto。件名＋本文=対象チャンク一覧・使えた数・まとめ・追加候補）と「📋 内容をコピー」（clipboard、✓フィードバック）。「🔁 もう一度 / ホームへ戻る」。

### 8.14 表現ストック（`ExpressionStock.tsx` + `useStock`）

### 8.15 教材化プレビュー（`StockEnrich.tsx` + `lib/enrich.ts`）
表現ストックの英文（＋あれば和訳）に、AI が**和訳・例文1件・シラブルカナ・分類（Type/Category/Level）**を補完し、確認・修正してからデッキへ直接追加する画面。「蓄積 → 教材化 → 練習」をアプリ内で完結させる（要件 §4.20）。

- **①対象選択**: ストック全件を既定ONで一覧。デッキ収載済み（`chunkMatch.normalize` の正規化一致）はグレーアウトして対象外（重複防止＋API節約）。
- **②生成**: 「✨ 生成する（n件）」を押したときだけ AI を呼ぶ。**5件ずつのバッチを直列実行**（`enrichAll`、進捗バー・中止ボタン）。仕様は §13.7。
  - **APIエラーで中断した場合**は成功済みバッチのドラフトを保持したままプレビューへ進み、エラーバナーに「**↻ 残りn件をもう一度生成する**」を表示（`retryPlan`: 未生成の targets と挿入位置を記憶し、続きからだけ再実行）。キー無効（`auth`）は設定の修正が先なのでボタンを出さない。
- **③ドラフト確認**: 生成結果をカードで一覧。**訳・カナ・例文・例文訳・例文カナは編集可**（編集のたび `lintKana` で即時再検証）、Type/Level はセレクト、Category は既存カテゴリの datalist つき自由入力。
  - カナ検証（§13.8）の不合格は「⚠ カナ要確認: 理由」を表示。**保存は妨げず**、そのまま追加すると `kanaWarnings` フラグ付きで保存される。
  - 例文が空のドラフトは警告表示（穴埋め・瞬間英作文の対象外になる旨）。
  - 生成に失敗した項目は error 表示＋「失敗した項目をまとめて再生成」。各カードは「除外」チェックで対象から外せる。
- **④追加**: 「📚 デッキに追加（n件）」→ `draftToPhrase`（id=`stableId(en)`・status=未着手・createdTime=現在時刻）→ `useDeck.addPhrases` → **追加できた項目をストックから削除** → 完了画面（「今日の練習へ」「チャンク一覧を見る」）。
- APIキー未設定時は設定画面への誘導（チャット練習と同様）。

### 8.16 AI長文作成（`LongReadingCreate.tsx` + `lib/longGen.ts`）
テーマ・難易度・長さと、デッキから選んだ**チャンク3〜5個**を指定して、長文音読用の読み物（英文＋和訳）を AI に生成させる画面。蓄積したチャンクを長文の中で再利用し、チャンク練習と長文練習を分離させない（要件 §4.21）。

- 入力: テーマ（自由入力＋チップ候補: 日常/仕事/健康/旅行/雑談）、難易度（Basic≒A2 / Core≒B1 / Advanced≒B2）、長さ（短め=1段落60〜100語 / 長め=2段落120〜180語）、チャンク選択（`excludeLongReading` したデッキから検索＋チェック。**SRS期日到来分を先頭に提示**し「今日」バッジ表示。3〜5件でないと生成不可）。
- 生成: 1リクエスト1本（§13.7。temperature 0.6）。生成中は中止可能。
- プレビュー: タイトル（英/日）・本文・和訳を**編集可**。指定チャンクの**含有チェック**（`matchesChunk`）を ✓/✗ チップで表示（✗でも保存可・「↻ もう一度生成」あり）。
- 保存: `draftToLongPhrase`（`type='Long Reading'`・本文は `examples[0]`・**カナなし**・category=テーマ・note に使用チャンク・id=`stableId(タイトル+本文先頭64字)`）→ `addPhrases` → `/long-reading` へ遷移（createdTime 降順で先頭に来るため、そのまま音読を始められる）。

### 8.17 チャンク編集/追加（`ChunkEdit.tsx` + `lib/phraseForm.ts`）
教材の全フィールドを CSV 往復なしで修正・追加するフォーム。`/chunk/:id/edit`（編集）と `/chunk/new`（新規）を同一コンポーネントで賄う。

- **フォーム**: 英語/日本語訳/カナ（共通 `FormField`）、Type/Level セレクト（`TYPE_OPTIONS`/`LEVEL_OPTIONS`。既存値が候補外でも温存表示）、カテゴリ（既存カテゴリの datalist つき自由入力）、Priority、ステータス（`ALL_STATUSES`）、Note（textarea）、**例文カード×可変**（英文/訳/カナ＋行削除、「＋ 例文を追加」は最大 `MAX_EXAMPLES`=5 まで）。
- **ドメインロジックは `lib/phraseForm.ts` の純関数**: `phraseToDraft` / `emptyDraft`（既定 Chunk/Core/未着手）/ `validateDraft`（en・ja 必須。未入力時は保存ボタン disabled＋理由表示）/ `draftKanaIssues`（`lintKana` をレンダー時導出。警告は入力欄直下に amber 表示）/ `draftToPhraseFromForm`。
- **保存規則**（`draftToPhraseFromForm`）: 全フィールド trim・**英文が空の例文行は除外**（残りは詰められ、カナ要確認ラベルも詰め後の番号）。`kanaWarnings` は `lintPhraseKana` で**保存のたびに再計算**（正しいカナに直せば「要確認」が解除される）。**編集時は id と createdTime を既存値のまま維持**（英文を変えても SRS 進捗・並びを保持）。新規時は `id = stableId(en)`・`createdTime = 現在時刻`（アプリ内追加の印。マージ取り込みで保持される）。
- **重複防止**: 保存時に**正規化した英文**（`chunkMatch.normalize`。教材化のデッキ収載チェックと同じ）で既存デッキと比較し、一致があれば保存せず「既にデッキにあります」＋該当チャンクへのリンクを表示。編集時は自分自身を除いて判定する。ID 比較にしないのは、編集で id を維持する仕様のため英文改名後の重複を検出できないから。
- 保存後は `/chunk/:id`（詳細）へ replace 遷移（`ids`/`backTo` を引き継ぎ）。「← 戻る（保存しない）」は `navigate(-1)`。
- 導線: チャンク詳細の「✏️ 編集」（§8.11）とチャンク一覧の「＋ 追加」（§8.5）。

## 9. 音声仕様（`src/lib/tts/` — エンジン差し替え式）

読み上げは `src/lib/tts/index.ts` を唯一の窓口とし、実行環境でエンジンを切り替える（公開APIは両者で同一）:

| | Web/PWA（`webSpeech.ts`） | ネイティブアプリ（`capacitorTts.ts`） |
|---|---|---|
| エンジン | Web Speech API（speechSynthesis） | Android システムTTS（`@capacitor-community/text-to-speech`。**WebViewにはspeechSynthesisが存在しない**ため） |
| 発話の連鎖 | utterance の onend/onerror | speak() の Promise 解決（世代カウンタで stop 後のコールバックを無効化） |
| 声の一覧/選択 | getVoices()。共通の `pickVoice.ts`（端末内優先・en-US/ja-JP優先） | getSupportedVoices()（同形状）。個別選択は voice index（効かない端末でも lang は反映） |
| Word Spark 境界 | onboundary（非対応エンジンは推定） | onRangeStart リスナー（同左） |
| アンロック | primeTTS()（iOS向け・初回ジェスチャ） | 不要（no-op） |

ネイティブエンジンは `isNativeApp`（`lib/platform.ts`、注入済み `window.Capacitor` を判定）のときだけ
dynamic import され、Webバンドルには混入しない。以下は共通仕様（旧 `lib/tts.ts` から不変）:

- `loadVoices()`: `getVoices()`／`onvoiceschanged`／500msフォールバックで音声一覧を取得。
- `getEnglishVoices()`: `lang` が `en` で始まる音声に限定。`hasVoiceForLang(prefix)`: 指定言語の音声有無を判定。
- `resolveVoice(voiceURI, lang)`: 指定があり言語が一致すればその音声、無ければ言語先頭一致で自動選択。
  **オフラインでも鳴るよう `localService`（端末内蔵）音声を優先**する。
- `speak(text, {voiceURI, rate, lang, onBoundary})`: 既存発話を `cancel` 後に発話。`lang` 既定 `en-US`。
  **`rate` は英語のみ適用、日本語（ja）は常に等倍**。Androidの無音対策として `voice` オブジェクトを明示割当。
  `onBoundary(charIndex)` は単語境界ごとに文字位置を通知（文境界 `name==='sentence'` は無視）。**対応エンジンのみ発火**し、
  Android Chrome の Google TTS 等では発火しないことがある（呼び出し側で推定タイミングにフォールバック。§9.1）。

### 9.1 Word Spark（読み上げ同期ハイライト。旧称: カラオケ式）
読み上げ中の単語をマーカー風（背景アンバー）に強調する横断機能。文字サイズは変えず折り返しが揺れない。
- `lib/spokenWords.ts`（純関数・テスト付き）: `wordSpans`（空白区切りの単語オフセット）/ `wordAtChar`（boundary の charIndex→単語番号）/
  `estimateWordTimings`（boundary 非対応エンジン向けの各単語開始時刻の推定）。推定は2段構え:
  - **全体の長さ**: 実際の発話時間（onstart→onend の実測）から rate 別の文字/秒を学習し
    `localStorage`（`my-phrases:tts-cal-v1`）に保存（`recordSpokenDuration` / `charsPerSecond`。
    指数移動平均 α=0.35、途中キャンセル等の外れ値は棄却）。実測が無い間は既定 15文字/秒 × rate。
  - **単語ごとの配分**: 音節数推定（母音グループ、`estimateSyllables`）＋機能語（冠詞・前置詞・代名詞・助動詞等の弱形）は×0.5、
    カンマ・文末句読点の後はポーズ加算。英語の強勢リズムに近い強弱で単語を送る。
- `hooks/useSpokenWordTracker.ts`: `start(text, rate)` を speak 直前に呼び、`onBoundary` / `onStart` / `onEnd` を speak に渡す。
  350ms 以内に boundary が来なければ**推定タイミングで単語を送る**ハイブリッド（boundary 到着で推定タイマー破棄）。
  `onStart` で推定タイマーを実際の発話開始時刻に引き直し（キャンセル待ち120ms・エンジン起動遅延のズレを吸収）、
  `onEnd` で実測時間を記録して速度学習に反映。`stop()` で消灯（停止・終了・カード切替時）。
- `components/SpokenText.tsx`: `wordSpans` で分割し `current` 番目をハイライト描画。
- 適用箇所: 長文音読の本文（§8.4）、`ReproCard` の開示英文＋「🔊もう一度」（§8.2 / §8.6b / §8.7 / 今日の練習）、
  **`ExampleList` の例文行**（チャンク詳細・今日の練習の5例文表示。🔊を押した行だけハイライト、他は表示のまま）。日本語読み上げは対象外。
- 再生し直し・別例文への切替時は**世代トークン**で旧発話の onEnd/onError を無視し、新しいハイライトが消えないようにする（`ExampleList` / `ReproCard`）。
- `speakSequence(parts, {voiceURI, rate, gapMs, isCancelled, onDone})`: `SeqPart[]`（`{text, lang?, gapAfter?}`）を順に発話。
  各パート後の間は `gapAfter`（無ければ共通 `gapMs`）。`isCancelled()` が真になると即中断。連続再生・今日の練習のお手本再生で使用。
- `primeTTS()`: iOS Safari の音声アンロック。`App` で最初の `pointerdown` 時に一度実行。
- 未TTS環境（API無し / 音声0件）では `SupportBanner` を表示して案内する。

### 9.2 音声認識（`src/lib/speech/` — エンジン差し替え式）【v1.6.1】

**Android の WebView は Web Speech API の「認識」を実装していない。** 厄介なのは
`webkitSpeechRecognition` が**コンストラクタとしては存在する**こと。「オブジェクトの有無」で対応判定すると
判定をすり抜け、ボタンは出るのに開始すると必ず失敗する。`speechSynthesis` が無いのと同じ構図なので、
読み上げ（§9）と同じ**エンジン差し替え方式**にした。

- `lib/speech/types.ts`: `SpeechEngine`（`isAvailable()` / `ensurePermission()` / `start(lang, listeners)` / `stop()`）と `SpeechListeners`（`onFinal` / `onPartial` / `onError` / `onEnd`）。
- `lib/speech/index.ts`: 既定は `webSpeechEngine`。`isNativeApp` のとき `import('./capacitorSpeech')` で差し替え（**dynamic import なので Web バンドルに混入しない**。ビルド出力で別チャンクになることで確認できる）。`engineReady` / `speechEngine()` を公開。
- `lib/speech/webSpeech.ts`: Web Speech API（`continuous`/`interimResults` ON）。`start()` の中で認識器を生成する。
- `lib/speech/capacitorSpeech.ts`: `@capacitor-community/speech-recognition`。**`ensurePermission()` が Android の権限ダイアログを出し、アプリを権限マネージャに載せる**（`AndroidManifest.xml` に `RECORD_AUDIO` が必要。プラグイン側 manifest が Android 11+ 必須の `RecognitionService` `<queries>` も持つ）。**Android の `SpeechRecognizer` は無音で自動終了する**ため、`listeningState='stopped'` で直前の部分結果を確定扱いにし、利用者が停止するまで 300ms 後に自動再開する。無音のまま3回続けて再開したら諦める（暴走防止）。
- `lib/speech/messages.ts`: 認識エラーコード→日本語メッセージ（`not-allowed` / `no-speech` / `audio-capture` / その他）。
- `hooks/useSpeechInput.ts`: `{ supported, listening, interim, error, start, stop }`。**対応判定は非同期**（`engineReady` → `isAvailable()`）。`onFinal` は ref 経由で保持し、親の再レンダーでエンジンを作り直さない。
- `components/VoiceInput.tsx`: 日本語入力欄用のマイクボタン（§16.7 の STEP1/2）。**ネイティブでは既定で出さず、キーボードのマイクキーを案内する**（v1.6.2。Android の音声認識は無音で切れるため**長文入力では途切れる**。キーボードのマイクは連続入力できる）。設定 `inAppMic` でアプリ内ボタンも出せる。
- `lib/speechText.ts`: `appendSpoken(current, fragment, {newline})` — 確定した発話を既存テキストへ足す純関数（意味ノードは1発話=1行、自由記述は空白区切り）。

## 10. スリープ抑止・バックグラウンド再生仕様（`src/lib/wakeLock.ts` / `keepAlive.ts`）

- `useWakeLock(active)`: `active` の間だけ Screen Wake Lock を取得し画面スリープを抑止。
- タブが裏に回ると Wake Lock は自動解放されるため、`visibilitychange` で復帰時に取り直す。
- 非対応端末・ユーザー操作外では黙って諦める（再生自体は継続）。
- 連続再生プレイヤーが `playing || dark` の間に使用する。

### 10.1 【実験的】バックグラウンド再生キープアライブ（`keepAlive.ts`）

画面オフ・タブ非表示でページが凍結されると `speakSequence` の `onend`→`setTimeout` 連鎖が死んで再生が止まる。
一方でブラウザは**「音声を再生中のタブ」を凍結・タイマー抑制の対象外**にするため、連続再生中にほぼ聞こえない
実音声をループ再生してタブを生かし、画面オフでも読み上げの継続を**試みる**（設定 `bgPlayback`、既定OFF）。

- **キープアライブWAV**（`generateKeepAliveWav`）: 40Hz正弦波・振幅0.02（≈-34dBFS）・8kHz・16bitモノラル・**30秒**を実行時生成（Blob URL。アセット不要・オフライン可）。
  30秒=1200周期ちょうどでループ境界が位相連続（クリック音なし）。**Android Chrome は5秒未満のメディアを
  メディア再生として扱わない**（通知が出ず凍結免除も受けられない）ため、5秒を大きく超える長さにする（v0.11.1）。**デジタル無音は「再生中」と判定されない**ため微小振幅の実音声を使い、`volume` は 1 のままサンプル振幅側で静かさを確保する。
- **開始**（`startKeepAlive({title, artist, onExternalPause, resilient?, useMediaSession?})`）: autoplay 制限のため**ユーザージェスチャ（▶/🌙/🔊のタップ）内で同期的に呼ぶ**。拒否・非対応時は false を返し従来動作（Wake Lock のみ）で続行。
  後ろ2つはネイティブアプリ用（§10.2）: `resilient` は外因停止時に再生全体を止めず鳴らし直す（上限10回）、`useMediaSession: false` は Media Session を使わない。
- **Media Session**: 通知/ロック画面に再生中の教材（英文/和訳・アプリアイコン）を表示。**⏸/⏹操作は再生全体を停止**（キープアライブだけ止まってハックが静かに死ぬのを防ぐ）。play は v1 では no-op（ロック画面からの再開は将来）。カード送りは `updateKeepAliveMetadata` で反映。
- **外因停止**: 通知の⏸・イヤホン取り外し・他アプリの音声フォーカス奪取で `pause` された場合は `onExternalPause` で TTS ごと停止する。
- **停止**（`stopKeepAlive`）: 冪等。再生停止・ページ離脱の全経路で呼ぶ。Media Session の後始末も行う。
- Wake Lock とは**併用**（補完関係）: 画面点灯中はロックが消灯を防ぎ、電源ボタンで消灯されたらキープアライブが凍結回避を試みる。
- **非公式ハックであり保証なし**: 効果は端末・Chrome の省電力実装に依存し、将来のブラウザ更新で無効化され得る。iOS Safari では効果がない。効かない端末では従来の 🌙（§8.7）か、ネイティブアプリ（§10.2）を使う。

### 10.2 ネイティブアプリのバックグラウンド再生（`PlaybackService` + `BackgroundPlaybackPlugin`）

ネイティブアプリでは Android が公式にサポートする方式で画面オフ再生を実現する。**プロセスの生存（FGS）と
WebViewページの生存（キープアライブ音声）は別問題**であり、v1.2.1 で両方を併用する構成になった:

- **mediaPlayback 型フォアグラウンドサービス + PARTIAL_WAKE_LOCK**（`android/…/PlaybackService.java`）。
  画面オフでもプロセス・CPU・システムTTSが動き続ける。
- **キープアライブ音声を併用**（v1.2.1）。FGS だけでは 30〜60秒で再生が止まった。音を鳴らしているのは
  Android のシステムTTS（別プロセス）で **WebView 自身は無音**のため、画面オフの WebView が
  「非表示かつ無音のページ」として Chromium に凍結され、`speakSequence` の連鎖（TTS完了コールバック→setTimeout）
  ごと止まっていた（画面を点けると凍結が解けて再開する）。§10.1 の仕組みをネイティブでも走らせ、ページを
  「音声再生中」にしておく。ネイティブ用に `resilient`（外因停止時は再生全体を止めず鳴らし直す。
  停止操作はアプリ内の⏸で行うため）と `useMediaSession: false`（FGSの通知が同じ役目を持つ）を指定する。
- **レンダラ優先度**: `MainActivity` で `setRendererPriorityPolicy(RENDERER_PRIORITY_IMPORTANT, false)` を明示し、
  WebView 非表示時にレンダラプロセスの優先度が下げられないようにする。
- JS側は `lib/backgroundSession.ts` の共通ファサード（start/update/stop）経由。**Webは keepAlive（§10.1）のみ、
  ネイティブはプラグイン（`lib/native/backgroundPlayback.ts`）＋keepAlive の併用**。
  連続再生（§8.7）・長文音読（§8.4）が使用。
- 通知に再生中のチャンク（英文/和訳）を表示し、カード送りで更新。停止・ページ離脱で通知も消える。
- Android 13+ は初回再生時に通知権限（POST_NOTIFICATIONS）を要求。**拒否されても再生は動く**（通知が出ないだけ）。
- ネイティブでは常時ON（設定不要）。🌙暗くして再生ボタンは不要になるため**ネイティブでは非表示**（Webのみ）。

  - 運用: `CHANGELOG.md` を更新し `npm run bump:*` で番号を上げ、PRをmainへマージするだけで採番される。

## 12. 既知の制約・注意

- 発音採点は自己申告（音声認識は未実装）。
- TTSの声・品質は端末依存。日本語訳の読み上げ・再現練習は日本語音声がある端末でのみ有効。
- CSVは `ID` 列を id に採用。`ID` 列が無い旧データは英文ハッシュIDで代替（英文変更で別チャンク扱い）。
- 例文の日本語訳は元データ側（`日本語訳{n}` 列）に持たせる。空の場合は再現練習・和訳読み上げでその項目をスキップ。
- インポートは既定マージ（§6.5）。**Notion側で削除した行はマージでは消えない**＝削除を反映したいときは全置換オプションを使う（アプリ内追加分は消えるため、先にCSVバックアップを取る）。
- AI生成（教材化・長文・カナ）は**下書き品質**。カナは kanaLint（§13.8）の機械検証のみで発音的な正しさまでは保証しない。要確認フラグ付きデータは時々CSVで書き出して人間（ChatGPT/Claude）が監査する運用を想定。
- 【Web/PWA限定】**Web Speech API は画面消灯・タブ非表示で再生が停止する**ため、連続再生は画面点灯（Wake Lock）が前提。
  実験設定「🔋 画面オフでも再生を試す」（§10.1）ONで継続を試みられるが、端末・ブラウザ依存で保証はない。
  **確実な画面オフ再生はネイティブアプリ（§10.2）で提供**。なお Android WebView には speechSynthesis が存在しないため、
  ネイティブアプリの読み上げはシステムTTS直結（§9）であり、この制約自体を受けない。
- **「暗くして再生」はバックライトを物理的に消す機能ではない**（Webに明るさ制御APIが無い）。
  画面を黒く塗るのみで、有機ELなら実質消灯に近く、液晶では手動で明るさを下げると効果的。
- 画面オフ・バックグラウンド再生は**ネイティブアプリ（§10.2）で対応**（v1.0.0、v1.2.1 で長時間の継続を修正）。
  再生を進めているのは WebView 内の JS 連鎖なので、**FGS だけでは足りず WebView ページ自体を生かす必要がある**点に注意
  （この層をいじるときは必ず画面オフで数分以上の実機確認をすること）。Web/PWA側の確実な対応には実音声ファイル（MP3）方式が必要だが、ネイティブ対応により優先度は下がった。
- **チャット練習・教材化・AI長文はオンライン必須**（他機能はオフラインで動作）。無料枠のレート制限（429）に達した場合は時間を置く。会話文・対象チャンク・教材化対象の表現（英語・和訳）は Gemini API へ送信される。
- チャンク使用検出は活用形非対応（`come down with` に対し `came down with` は不一致）。会話履歴はアプリ再起動で消える（タブ移動では保持）。
- 表現ストックは端末内のみ（端末間同期なし）。PC への受け渡しはタブ区切りコピーまたはメールで行う。

## 13. AI連携仕様（`src/lib/chatApi.ts` / `coachPrompt.ts` / `suggestions.ts` / `aiJson.ts` / `enrich.ts` / `longGen.ts` / `kanaLint.ts`）

チャット練習（§8.13）・教材化（§8.15）・AI長文作成（§8.16）が使う、Gemini API の OpenAI 互換エンドポイントとの連携仕様。SDK は使わず fetch のみ（バンドル肥大回避）。生成系（教材化・長文）も同じ `streamChat` を土台にする。

### 13.1 エンドポイント・リクエスト
- `POST https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`
- ヘッダ: `Content-Type: application/json` / `Authorization: Bearer <chatApiKey>`
- ボディは互換性の癖を避けるため **`model` / `messages` / `stream: true` / `temperature`（既定 0.7）のみ**送る。
- 既定モデル `gemma-4-31b-it`（Gemini API 上の Gemma 4 は**無料枠のみ**のモデルで課金が発生しない）。設定の選択式で `gemini-flash-latest`（応答が速め）へ切り替え、または「その他（手入力）」で任意のモデル名を指定できる（§8.8）。モデルはチャット練習・教材化・AI長文で共通。

### 13.2 SSE ストリーミング（`streamChat` / `parseSseChunk`）
- `fetch` + `ReadableStream` で受信し、SSE を逐次パースする: 空行区切りのイベントから `data:` 行を抽出、`[DONE]` で終端、CRLF 吸収、**イベント境界が未着の末尾チャンクは持ち越し**（`parseSseChunk(buffer) → {events, rest}`。単体テスト対象）。
- 各イベントの `choices[0].delta.content` を `onDelta` で通知し、完了時に全文を返す。`AbortSignal` で中断可能。
- `res.body` が無い環境では全文を一括受信して同じパーサに通すフォールバック。

### 13.3 エラーマッピング（`ChatApiError`）
| 条件 | kind | UI表示（§8.13） |
|---|---|---|
| 401 / 403 | `auth` | APIキーが無効 |
| 429 | `rate` | 利用上限。少し待ってから再試行 |
| fetch 失敗（`navigator.onLine === false` を判別） | `network` | オフライン / 通信失敗 |
| 5xx | `server` | 一時的なエラー・混雑の可能性（下記の自動再試行後） |
| その他の非2xx | `server` | サーバーエラー（本文先頭を添付） |

- **一時的な 5xx の自動再試行**: 無料枠の混雑などで散発する `500 INTERNAL` 等を吸収するため、`streamChat` は 5xx を受けたら **0.8秒 → 1.6秒 のバックオフを挟んで最大2回**（`TRANSIENT_RETRIES=2` / `RETRY_BASE_MS=800`）自動で再リクエストする。再試行するのは**本文受信前の失敗のみ**（応答の重複なし）。待機は `AbortSignal` で中断可能（中止ボタンが効く）。**429 は対象外**（再試行が上限消費を悪化させるため）。チャット・教材化・AI長文の全AI機能に共通で効く。
- エラー時も会話履歴は保持し、`retryLast` で同じ履歴から再送する。

### 13.4 Gemma 系の癖への対応
- **`system` ロール拒否**: 400 が返り先頭が system の場合、`foldSystemIntoUser` で system 文を最初の user メッセージへ前置して**1回だけリトライ**する。
- **内部思考タグ**: 応答冒頭に `<thought>…</thought>`（`<thinking>` / `<think>` も同様）を出力することがあるため、`stripThoughts` で**表示・履歴送信・まとめの全て**から除去する。ストリーミング途中で閉じタグ未着の間は開きタグ以降を隠す（本文が届き次第表示）。
- **チャット練習の出力形式は素のテキスト＋行頭マーカー規約**（会話では JSON を使わない。Gemma の JSON 遵守が不安定なため。構造化データが必須な生成系の対処は §13.7）:
  - `✏️ ` 行 = 訂正・より自然な言い方（会話ルールとしてプロンプトで指示）
  - `➕ 英語表現 — 日本語訳` 行 = まとめ末尾の追加候補。`lib/suggestions.ts` の `extractSuggestions` が行単位でパース（箇条書き記号・引用符・`—`/`–`/` - ` 区切りを許容）し、`filterNewSuggestions` が**デッキ収載済みの表現を正規化一致で除外**する。

### 13.5 プロンプト（`coachPrompt.ts`）
- `buildSystemPrompt(targets, feedbackJa, focus?)`: コーチのペルソナ＋対象チャンク一覧（en・ja）＋**話し方の規約**（基礎語彙・1文5〜6語・シンプル構造・日常/ビジネスで使い回せるフレーズ・1〜3文＋質問）＋訂正規約（✏️、解説言語は設定に従う）＋思考タグ禁止。`focus` 指定時は「今このチャンクを練習したい」（例文指定時はその場面を会話の中心に）を注入。
- `buildKickoffPrompt()`: コーチが先に挨拶する非表示ユーザーターン。
- `buildSummaryPrompt(feedbackJa)`: まとめ（使えたチャンク・アドバイス2〜3点・締めの一言・➕ 追加候補2〜4件、200語以内・質問禁止）。

### 13.6 セキュリティ・キャッシュ
- APIキーは `useSettings`（localStorage）にのみ保存し、Google のエンドポイント以外へは送らない（NFR-03）。
- Service Worker はこのオリジンに runtimeCaching を設定しない（POST はプリキャッシュ対象外。オフライン時は `network` エラーとして表示）。

### 13.7 AI生成（教材化 `enrich.ts` / 長文 `longGen.ts` / 共通 `aiJson.ts`）
生成系は自由文ではなく**固定スキーマの JSON** を返させ、アプリ側で厳格に検証する。

- **JSON抽出（`aiJson.extractJson`）**: `stripThoughts` → コードフェンス除去（`stripCodeFences`）→ 最初の `[` / `{` から対応する閉じ括弧まで（文字列リテラル考慮）を切り出して `JSON.parse`。失敗は throw し、**プロンプト末尾に「raw JSON only」を追記して1回だけリトライ**。それでも駄目なら error 付きドラフト（バッチ全体は捨てない）。
- **教材化（`enrich.ts`）**:
  - 入力 `EnrichInput {en, ja?}`。プロンプトに `(ja: given "…")` / `(ja: MISSING)` を明示し「given はコピー・MISSING のみ生成」。**アプリ側でも given 項目はモデル出力を無視して入力値を採用**（防御）。
  - 出力はフラットキーの JSON 配列（`n / en / ja / kana / example_en / example_ja / example_kana / type / category / level`）。`n` で入力と突合し、件数不一致は欠けた項目だけ error 化。type/level は候補外なら既定値（Chunk / Core）へ丸める。category はデッキの既存カテゴリ一覧をプロンプトに列挙して選ばせる。
  - プロンプトにシラブル記法ルール＋few-shot（`docs/シラブル音節記法.md` の例）を埋め込む。生成後に `lintKana` を通し、結果をドラフトに同梱。
  - **コスト対策**: ボタン起点のみ生成 / デッキ収載済み・和訳ありは生成対象から除外 / 例文は1件固定 / **5件バッチ**（記法ルール部分のプロンプトを共有）/ `temperature: 0.2` / リトライは各バッチ1回。
  - `ChatApiError` はバッチ処理を中断し、成功済みドラフト＋エラーを UI へ。UI 側は未生成の残りを「↻ 残りn件をもう一度生成する」で続きから再開できる（§8.15。5xx は §13.3 の自動再試行を挟んだ後）。
- **長文（`longGen.ts`）**: 1リクエスト1本、JSON オブジェクト（`title_en / title_ja / en / ja`、本文の段落は `\n\n`）。`temperature: 0.6`（読み物の多様性と JSON 遵守のバランス）。生成後に `matchesChunk` で指定チャンクの含有をチェックし UI に表示。

### 13.8 シラブルカナ検証（`kanaLint.ts`）
AI が生成したカナの**下書き**を機械検査する最小リンター（`docs/シラブル音節記法.md` §1〜2 の機械化。発音的な正しさまでは判定しない）。

| 種別 | 検査項目 |
|---|---|
| error（書式違反） | 許容文字集合（カタカナ・ー・`・`・半角空白・`‿`・`( )`・`*` のみ）/ `*` のペア・空強勢・強勢内カナ必須 / 丸かっこの開閉・入れ子・空・中身カナのみ / 区切り記号の行頭行末・連続・スペース隣接 / 空文字 |
| warn（要注意の兆候） | 単語数整合（カナ語数〈空白区切り＋`‿`加算〉が英語語数超過 or 半分未満）/ 3語以上の文で強勢ゼロ |

- `lintKana(kana, en): KanaIssue[]`（空配列=合格）、`lintPhraseKana(p): string[]`（不合格フィールドのラベル `音節` / `音節{n}`）。
- error / warn のいずれかがあれば **`kanaWarnings` フラグ付きで保存**（保存自体は妨げない）。教材化プレビュー（理由つき）・チャンク編集（§8.17、入力欄直下に理由つき）・チャンク詳細（⚠バッジ）に表示し、CSV「カナ要確認」列で書き出して定期監査に使う。チャンク編集で正しいカナに直して保存するとフラグは解除される（`lintPhraseKana` で保存のたびに再計算）。

### 13.9 無料枠の残り目安（`usage.ts` + `UsageBadge.tsx`）
Gemini API は残クォータを返さないため、**このアプリから実際に送った HTTP リクエスト数を端末内で日次集計**し、既知モデルの無料枠 RPD（1日あたりリクエスト数）との差分を「残り 約n回」として示す。

- **計上点**: `chatApi.requestStream`（実際に fetch する唯一の場所）。5xx 自動再試行や system ロールの折りたたみ再送も**1回ずつ数える**（実際に上限を消費するため）。チャット練習・教材化・AI長文の全AI機能が対象。
- **保存**: `useUsage`（zustand、localStorage キー `my-phrases-usage`）。`{date, counts: {モデル名: 回数}}`。
  `date` は**太平洋時間の日付**（`pacificToday`、`Intl.DateTimeFormat` + `America/Los_Angeles`）— Google の無料枠が太平洋時間の深夜（日本時間の夕方16〜17時ごろ）にリセットされるため。日付が変わっていれば 0 から数え直す。localStorage が使えない環境ではメモリ内カウントのみ（テスト等）。
- **RPD 目安**（`freeTierDailyLimit`、名前の部分一致）: gemma → 14,400 / flash-lite → 1,000 / flash → 250 / pro → 100 / 未知 → undefined（回数のみ表示）。Google が予告なく変更するため参考値と明記する。
- **表示**（`UsageBadge`）: `⚡ 無料枠の目安: 残り 約n回（今日 m回使用）`。チャット練習（チップ下）・教材化プレビュー・AI長文作成・設定（AI）に表示。設定には「この端末のこのアプリからの回数のみ（AI Studio・他端末は含まれない）」の注記を置く。

### 13.10 意味ノード英語思考のAI呼び出し（`thinkPrompt.ts`）
意味ノード英語思考（§16.7）は同じ `streamChat` を土台に**Gemma を2回**呼ぶ。プロンプト組み立てとパースは `lib/thinkPrompt.ts` に純関数として分離し（UI から独立・vitest 対象）、応答は §13.7 と同じ固定スキーマJSON方式（`extractJson` でパース、失敗時は「もう一度」ボタンで再実行）。温度は既定（0.7）。

- **①分解評価（`buildDecomposePrompt(thought, nodes)`）**: system に評価基準（1ノード=1機能・骨子か・結論先出しか・要素の欠落・ノード数2〜5）と出力スキーマ、user に元の思考と学習者の分解。`parseDecomposeFeedback` が `{comment, nodes:[{node, ok, issue, fix}], suggested:[…]}` を返す（`nodes` が配列でなければ throw、個別フィールド欠損は空文字/false に丸め）。
- **②英文チェック（`buildEnglishPrompt(nodes, sentences)`）**: 訳の正しさより「平易・シンプル・ビジネスで通用」を重視し、学習者の文を活かした**最小修正**を提案させる。`parseEnglishFeedback` が `{comment, scene, sentences:[{original, ok, issue, suggestion, reason}], expressions:[{en, ja}]（0〜3件）}` を返す（`sentences` が配列でなければ throw、`scene` 空なら `'自分の思考'`、`suggestion` 空なら原文で代替）。`scene` は保存カードの `category` に使う。

## 14. 学習ログ・KPI・ゴール仕様（`lib/events.ts` / `kpi.ts` / `goals.ts` / `playTracker.ts`）

学習エンジン（練習機能）を日常の時間軸に載せる基盤（学習OS化フェーズ0）。行動を追記型ログに残し、そこから日次KPIとゴール進捗を算出する。SRS進捗（`progress`）が「今の状態」なのに対し、学習ログ（`events`）は「行動の履歴」で補完関係にある。

### 14.1 イベント型（`lib/events.ts`）
`LearningEvent` は type による判別ユニオン。共通フィールドは `id`（ランダム）・`ts`（ISO）・`date`（ローカル `YYYY-MM-DD`・`events` の索引）・`type`。

| type | 追加ペイロード | 発火点 |
|---|---|---|
| `grade` | `chunkId, grade, boxFrom, boxTo, mode?, latencyMs?, predicted?, launchMs?, attempt?, autoMatch?` | `useDeck.grade`（全採点の唯一の関門）。`boxFrom<4 && boxTo>=4` で「定着への昇格」を判定 |
| `chat` | `targetChunkIds, usedChunkIds, userMessageCount` | `useChat.requestSummary` 完了時→`useDeck.noteChatComplete`（**1セッション＝まとめ完了**を単位に記録）。**usedChunkIds をここで永続化**（従来は終了で消えていた） |
| `play` | `seconds` | `usePlayTracking`→`useDeck.notePlayback`（連続再生・長文音読） |
| `materialize` | `addedCount` | `StockEnrich.save`（教材化してデッキ追加） |
| `think` | `nodeCount, sentenceCount, savedCard` | `ThinkPractice`→`useDeck.noteThinkComplete`（意味ノード英語思考の英文チェック完了を**1セッション**として記録。§16.7） |

- `grade` の任意項目（追加時期と用途）:
  - `latencyMs`【v1.3.0】和訳表示→**開示タップ**まで。**速さの指標としては使わない**（§16.4 の経緯）。互換のため残置
  - `predicted`【v1.7.0】`'can' | 'unsure'`。開示**前**の申告（§17.1）。較正の母数
  - `launchMs`【v1.9.0】和訳表示→**発話開始**まで。ゴールの `fastLaunchPct` はこれを使う（§16.4）
  - `attempt`【v1.9.0】音声認識が拾った実際の発話（証拠として保存）
  - `autoMatch`【v1.9.0】`'hit' | 'partial' | 'miss'`。自動照合の結果。**加点のみに使い減点には使わない**
  - いずれも**任意項目**。`events` ストアはオブジェクトごと保存する設計のため**DBマイグレーション不要**で追加できた
- `makeEvent(type, payload, now?)` が `id/ts/date` を補完。`now` を引数化しテストで固定できる。
- 記録は全て **best-effort**（`logEvent` を try/catch で囲み、失敗しても採点・チャット等の本処理を止めない）。`grade`/`play`/`chat` はログ成功時にストア `events` へも追記して即時にホームへ反映（`play`/`chat` は共通ヘルパー `logAndMaybeStreak` で最低ライン到達ならストリークも更新）。`materialize` は `refreshEvents()` で読み直す。

### 14.2 KPI集計（`lib/kpi.ts`・純関数）
`events: LearningEvent[]` だけを入力に取り IndexedDB に触れない（テスト容易・UIから独立）。

- `eventsOn(events, date)` / `eventsInRange(events, from, to)`: 日付での絞り込み。
- `gradeCount` / `chatMessageCount` / `thinkSentenceCount` / `outputCount`（採点＋チャット送信＋英語思考の英文数）/ `playSeconds`。
- `retainedPromotions(events)`: 期間内に box≧`RETAINED_BOX`(=4) へ昇格したユニークチャンク数。
- `chatUsedRate(events)`: 期間内チャットの `used/target` 合算と率。
- `minimumLineMet(dayEvents)`: その日の**最低ライン**達成判定＝採点 or チャット完了 or 英語思考完了（`grade`/`chat`/`think` イベントが1件でもある）、または `playSeconds >= MIN_LINE_PLAY_SECONDS`(=300)。
- `launchLatencyMedian(events)`: `latencyMs`（＝開示タップまで）の中央値ms。1件も無ければ `null`。**v1.9.0 以降、速さの評価には使わない**（§16.4 の経緯）。セッション完了画面の表示にのみ用いる。
- `calibration(events)`【v1.7.0】: 開示前の申告（`predicted`）と結果のズレ。`{can:{total,hit,rate}, unsure:{total,hit,rate}, sample}`。`grade==='good'` のみ hit。`predicted` を持たない採点は母数から除外。0件でも `rate` は 0（NaN を返さない）。§17.1
- `leniency(events)`【v1.9.0】: **甘さ指数**。`autoMatch==='miss'` なのに `grade==='good'` を付けた割合。`autoMatch` を持たない採点は母数外。誤認識も混じるため断定には使わない。§17.2
- `computeDailySummary(events, date?)`: ホーム「今日のあゆみ」用【v1.6.0 でホームからは撤去。関数は残置】（採点数・アウトプット・定着・最低ライン・**`latencyMedianMs`**＝当日の起動レイテンシ中央値、計測付き採点が無ければ `null`）。
- `computeWeeklyStats(events, to?)`: 直近7日の定着数・アウトプット・実戦投入率・活動日数。

### 14.3 ゴール設定（`lib/goals.ts`・`components/GoalProgress.tsx`）
- **梯子は「構造優先」（v1.5.0 改訂）**。学習診断の結論＝ボトルネックはチャンクの「量」でなく構造の「自動化」。よって序盤に**構文の反射化**（`retainedStructures`）と**英語思考の起動速度**（`fastLaunchPct`）を置き、チャンク量（`retainedChunks`）は土台として中盤に据える＝「量」から「速さ」への KPI 転換。**累計アウトプット数（`totalOutputs`）の段は撤去**（メトリクス自体は残置）。
- `GOAL_TRACKS`: **内蔵プリセット3種**（`business` / `study` / `daily`）。各トラックは `northStar`（最終ゴール）と `steps`（中間ゴールの梯子）を持つ。各ステップの `metric`（`retainedStructures` / `fastLaunchPct` / `retainedChunks` / `retainedInCategory` / `masteredChunks` / `chatUsedRatePct` / `chatSessions`）と `target` で達成度を測る。
  - 💼 ビジネス（6段）: 構文を反射（`retainedStructures` 12）→ 5秒で起動（`fastLaunchPct` 5000ms・70%）→ チャンク土台（`retainedChunks` 50）→ 3秒に短縮（`fastLaunchPct` 3000ms・60%）→ 会話で使える（`chatUsedRatePct` 60）→ ビジネス領域（`retainedInCategory`=Business transformation 20）。
  - 🎓 留学（5段）: 構文10枚（`retainedStructures` 10）→ 5秒で起動（60%）→ チャンク50 → チャット10セッション（`chatSessions`）→ 習得100（`masteredChunks`）。
  - 🗣️ 日常（4段）: 構文8枚（`retainedStructures` 8）→ 5秒で起動（60%）→ チャンク30 → 雑談（`chatUsedRatePct` 50）。
- **メトリクスの算出**（`measureStep`）: `retainedStructures`＝`type='Structure'` かつ box≧`RETAINED_BOX` のカード数。`fastLaunchPct`＝**直近7日**（`recentLatencies`）の **`launchMs`** 付き `grade` イベントのうち `thresholdMs` 以内だった割合（0-100・`Math.round`、対象0件なら0）。**v1.9.0 で `latencyMs` から `launchMs` へ切替**（§16.4）。`launchMs` は音声モードでのみ記録されるため、声で答えていない間は0件＝未計測になり、`nextActions` が設定への導線を示す。`GoalMetric.thresholdMs?` が起動レイテンシしきい値。`retainedChunks` / `masteredChunks` は **純チャンク数**（Sentence Engine〈構文・意味ノード〉と長文音読のカードを id で除外）。
- **target 値は実デッキ（488チャンク・2026-07-18 エクスポート）の分布に合わせて較正済み**。`retainedInCategory` の target はそのカテゴリの実在チャンク数を、`retainedStructures` の target は内蔵デッキの構文16枚を超えないこと（超えると到達不能になる）。
- `measureStep(metric, {phrases, progress, events})`: ステップの現在値を SRS進捗・学習ログから算出（純関数）。
- `computeTrackProgress(track, ctx)`: 各ステップの達成可否と、**全体達成率 `ratio`＝（達成ステップ数＋挑戦中ステップの部分進捗）／総ステップ数**、現在挑戦中ステップを返す。
- `nextActions(step, ctx)`【v1.6.0】: 挑戦中ステップを**「どの練習を何回やれば進むか」**へ翻訳して返す（`{emoji, label, to}[]`）。`0/12` という表示だけでは次の行動が分からないため。
  - `retainedStructures` / `retainedChunks` / `retainedInCategory` / `masteredChunks`: `gradesToRetain()` が「未定着カードを box の高い順に必要枚数ぶん取り、`threshold - box` を積算」して**必要な「できた」回数**を見積もる（デッキに足りない分は満額を上乗せ）。`masteredChunks` はしきい値 `MAX_BOX`。
  - `fastLaunchPct`: `fastLaunchGradesNeeded(fast, total, targetPct)` が `ceil((target*total - 100*fast) / (100-target))` で**分母も増える点を織り込んで**必要回数を出す。`total===0`（未計測）なら `null` を返し、設定で音声モードをONにする導線を示す。
  - 達成済み（`current >= target`）なら空配列。空なら見出しごと描画しない。
- `GoalProgress`: 未選択時はトラック選択カード（`setGoalTrack`）、選択後は北極星・`ratio`%・進捗バー・次のステップ（タップで全ステップ一覧を開閉）・「変更」・**最下部に「次のステップに進むには」**（`nextActions`）。ホーム最上位に置く（§8.1）。

### 14.4 連続再生の時間計測（`lib/playTracker.ts`・`hooks/usePlayTracking.ts`）
- `createPlayTracker(flush, opts?)`: 再生開始で生成。**`flushIntervalMs`(既定60秒)ごと**に経過秒を `flush` し、`stop()` で残りを flush（`minSeconds`(既定5)未満の端数は捨てる）。長時間の画面オフ再生中にアプリが落ちても取りこぼしを抑えるための間欠 flush。多重 stop は無視。
- `usePlayTracking(active)`: `active`(=`playing`) の間だけトラッカーを生かし、`flush` で `useDeck.notePlayback(seconds)` を呼ぶ。`PhraseDetail`（連続再生）と `LongReading`（お手本再生）が使用。
- `notePlayback`（再生）と `noteChatComplete`（チャット完了）は共通ヘルパー `logAndMaybeStreak(event)` を通す: イベントを記録し、当日の `minimumLineMet` を満たしていれば `bumpStreak`（§4.3）。これで「疲れた日は連続再生だけ」「短くてもチャットを1本完走」でもストリークが維持される。ログに失敗した場合はストリーク判定もしない（採点フローとは独立）。

### 14.5 永続化・バックアップ
- 学習ログは `events` ストア（§3.2）、選択中ゴールは meta `goalTrackId`。`load()` で全 `events` とゴールを読み込む。
- フルバックアップ（`backup.ts`、format:1）に `events?` / `goalTrackId?` を**任意フィールド**として追加。旧バックアップ（両方無し）も従来どおり復元でき、壊れた `events` は学習ログの欠落に留めて復元自体は継続する。復元時は `replaceEvents` で全置換。

## 15. 今日のプラン仕様（`lib/planEngine.ts` / `components/TodayPlan.tsx`）

「今日は何をどれだけやるか」をアプリが提案し、決断疲れ＝開始摩擦をなくす（学習OS化フェーズ1・要件 §4.26）。強制ではなく提案で、いつでも選び直せる。

### 15.1 編成ロジック（`lib/planEngine.ts`・純関数）
- `Energy = 'tired' | 'normal' | 'fresh'`。`ENERGIES` が 3択のアイコン・ラベルを持つ。
- `buildPlan(energy, ctx: { due, hasChatKey }): DailyPlan`（`{ energy, note, items: PlanItem[] }`）。Sentence Engine 導入後は**「構造優先」**に再編（§16。まず型の反射化から入る）:
  - **tired** → `[🎧 連続再生で流し聞き]`（`/browse`。5分で最低ライン到達＝ゼロの日を作らせない。不変）
  - **normal** → `[🧱 構文ドリル, ▶ 今日の練習]`（まず構文の反射化、そのあと期日ぶん。`due>0` なら「期日の{due}枚を…」、0なら「追加練習」に文面を切替）
  - **fresh** → `[🧱 構文ドリル, ▶ 今日の練習, 🧠 意味ノード生成, 💬 チャット練習]`。`hasChatKey` が false なら**意味ノード生成まで**の3項目（従来の瞬間英作文への置換は廃止）。
  - `PlanItem = { id, icon, label, detail, route, kind: 'play'|'daily'|'chat'|'structure'|'message' }`。**v1.8.0 で `'compose'` を削除**（`buildPlan` が compose の項目を生成せず、`planItemDone` の該当 case が到達不能なデッドコードだったため）。
- `planItemDone(kind, todayEvents): boolean` — 当日の学習ログから実施済みを判定（該当 mode の採点が1件以上で達成。相互に独立）:
  - `daily` = mode='daily' / `structure` = mode='structure' / `message` = mode='message' の採点
  - `chat` = 当日に `chat` イベントあり / `play` = 当日の再生秒数が `MIN_LINE_PLAY_SECONDS`(=300) 以上

### 15.2 画面（`TodayPlan.tsx`、ホーム §8.1）
- `planEnergy` が `null`（当日未選択）なら**体調ピッカー**（3択タイル）。選ぶと `useDeck.setPlanEnergy` が呼ばれる。
- 選択済みなら **`buildPlan` の結果**を表示: 体調＋方針の一言、各 `PlanItem` を1タップで `route` へ遷移するタイル。
  実施済み項目は `planItemDone` で **✅＋取り消し線**、全項目達成で「今日のプランは完了！」を表示。「気分を変える」で `clearPlanEnergy`。
- `due` は `computeStats(...).due`、`hasChatKey` は設定の `chatApiKey` 非空、`todayEvents` は `eventsOn(events, todayStr())` から。
- **状態の寿命**: 体調は meta（`planDate`=今日 / `planEnergy`）に保存し、`load()` が `planDate≠今日` で `null` に戻す（当日限り。§7.1）。

- プランへの**通知の入口**（`@capacitor/local-notifications`）は将来版。

## 16. Sentence Engine 仕様（三層学習構造・`lib/sentenceEngine.ts` / `pages/StructureDrill.tsx` / `MessageDrill.tsx`）

「単語→文」ではなく「**チャンク → 構文 → 意味ノード**」の三層で英作文を積み上げる学習構造（学習OS化フェーズ2）。狙いは、日本語で完成文を作ってから訳す癖を断ち、**和訳・意味の骨子を見た瞬間に英語の骨格へ飛び込む反射**を鍛えること。その反応速度を**起動レイテンシ**として計測しKPIにする。

### 16.1 三層の考え方
- **第1層 Chunk**（既存）: 語のかたまり・定型表現。瞬間英作文（§8.2）・穴埋め（§8.12）が扱う。
- **第2層 Structure（構文カード）**: 意味の骨格になる型（例 `X means that Y.` `What matters is X.`）。1つの型を色々な内容で**変形反復**して反射化する。
- **第3層 Message（意味ノードカード）**: 主張→根拠→補足のような複数ノードを並べたミニ・メッセージ。**日本語の完成文を作らず**、意味の骨子（ノード）ごとに主語と動詞を置いて英文を組み立てる。

### 16.2 データ表現（`public/data/sentence-engine.json` = 内蔵デッキ）
`Phrase` 型を流用し、専用 `type` で通常プールと区別する（長文音読と同じ「特殊 type は通常の練習・一覧・集計から除外」方式）。
- **構文カード**（`type='Structure'`、16枚）: `en`＝パターン文、`ja`＝意味機能つきの和訳、`examples`＝当てはめ変形5例（各 en/ja）。`category`＝意味機能（状態・定義 / 行為・影響 …）。
- **意味ノードカード**（`type='Message'`、50枚。id は `msg-01`〜`msg-50` 連番）: `en`＝改行区切りの参考出力ノード列、`ja`＝改行区切りの意味ノード列（主張:／根拠:／補足:）、`examples`＝`[]`。`category`＝場面（進捗報告 …。ビジネス・マーケティング中心）。
- 判定・読込ヘルパー（`lib/sentenceEngine.ts`）: `isStructure` / `isMessage` / `isSentenceEngine` / `excludeSentenceEngine`、`loadSentenceEngineSeed()`（`BASE_URL` 尊重で fetch）。
- **通常プールからの除外**: `useSession` は `filter` 未指定のとき `isSentenceEngine` を除外する。2ドリルは `filter` に `isStructure`／`isMessage` を渡して**あえて**その type だけを出題する（§5.1 / hooks/useSession）。

### 16.3 画面仕様（2ドリル）
共通骨格は瞬間英作文（§8.2）を踏襲: `SessionHeader`／`ReproCard`（日本語→タッチ→英文開示→タッチ）／末尾開示で `GradeButtons`／`StepNav`／最下部「✕ やめる」。`ReproCard` の拡張として `speakJa`（和訳面のTTS読み上げ可否・既定 true）と `revealNote`（開示英文の下の小さな注記）を追加。和訳面・開示英文面ともに `whitespace-pre-line` で改行ノードを行表示する。

- 【v1.6.0】**セット制**: 両ドリルとも `DRILL_SET_SIZE`(=10) 枚=1セットのランダム出題（`useSession` の `setSize` / `requeueWeak:false`）。**英文を一度でも開示すれば採点できる**（旧: カードの最後の例文まで開示が必要で、途中で送ると離脱するしかなかった）。セット完了時は `SessionSummary` に `setNumber` を渡し、紙吹雪＋「セット N 完了！」＋正答率＋全問正解の 🏆＋「次のセットへ →」を出す（`prefers-reduced-motion` で演出を停止）。
- **🧱 構文ドリル（`/structure`・`StructureDrill.tsx`）**: `useSession({ filter: isStructure, mode: 'structure', shuffle: true, setSize: DRILL_SET_SIZE, requeueWeak: false })`（**v1.6.0 で `clusterByFacet` を撤去**＝セット制のランダム出題と噛み合わないため）。カード上部に**構文パターンを常時表示**（意味機能チップ＝`category`＋パターン文 `en` を等幅寄りで強調＋`ja` を小さく）。出題項目は `examples` のみ（チャンク本体は含めない）。ガイド「日本語を見て、この構文で声に出して英作文 → タッチで答え合わせ」。
- **🧠 意味ノード生成（`/message`・`MessageDrill.tsx`）**: `useSession({ filter: isMessage, mode: 'message', shuffle: true, setSize: DRILL_SET_SIZE, requeueWeak: false })`。項目は1枚＝1項目（骨子 `ja` → 参考出力 `en`）。`speakJa={false}`（日本語は読み上げない）、`revealNote="参考出力（正解は一つではない）"`。meta は場面チップのみ。ガイド「意味の骨子から、日本語の完成文を作らずに英文を組み立てる → タッチで参考出力」。
- **内蔵デッキの空表示**（共通 `components/SeedDeckEmpty.tsx`）: 対象デッキが0枚なら「まだ〜デッキがありません」＋「📦 内蔵デッキを追加（構文16・意味ノード12）」ボタン。押すと `loadSentenceEngineSeed()`→`useDeck.addPhrases(seed)`（ロード中・失敗表示つき）。追加後は `useSeedDeck` フックが次レンダーで `s.restart()` を呼び、そのまま出題が始まる。

### 16.4 起動レイテンシKPI（Clause launch latency）
**v1.9.0 で終点の定義を変更した。** 当初は `shown → revealed`（和訳表示→**開示タップ**）を測っていたが、これは
**丁寧に言い直すほど値が悪化し、諦めて即開示すると良くなる**指標で、速さの評価に使えなかった（真面目に練習するほど
ゴールの `fastLaunchPct` が下がる利益相反）。終点を**発話開始**に変えて解消した。

- 計測器 `createLatencyMeter()`（`lib/sentenceEngine.ts`・純粋）:
  - `shown()` 新しい和訳が表示された（起点）
  - `launched()`【v1.9.0】**英語を言い始めた**＝音声認識の最初の中間結果。**1項目につき最初の1回だけ**採る（中間結果は何度も来るため）。`shown()` を経ていない呼び出しは無視
  - `revealed()` 英文を開示した
  - `median()`＝`solveMs`（開示まで）の中央値 / `launchMedian()`【v1.9.0】＝`launchMs`（発話開始まで）の中央値 / `reset()`＝カード切替でクリア
- 各ドリルは `ReproCard` の `onStep` から `shown()`/`revealed()` を、`onLaunch` から `launched()` を駆動し、採点時に
  `s.answer(grade, meter.median(), predicted, { launchMs: meter.launchMedian(), attempt, autoMatch })` を渡す。
- **ゴールの `fastLaunchPct` は `launchMs` のみを見る**（§14.3）。`launchMs` は音声モード（§17.2）でのみ記録されるため、
  声で答えていない間は0件＝未計測。`latencyMs` は互換のため残置し、`SessionSummary` の「⚡ 起動 X.X秒」表示にのみ使う。
- **目標値は 5秒 → 3秒**（目安 ◎3秒以内／○5秒以内）。

### 16.6 デッキ管理（別系統インポート/エクスポート）
Sentence Engine 教材（構文カード・意味ノードカード）を、チャンク（Notion往復用CSV）とは**別データ**として取り込み・書き出しする（設定「🧱 Sentence Engine デッキ」§8.8）。**CSVの列レイアウトはチャンクCSVと同一**（`DECK_CSV_HEADER`）で、新フォーマットは作らない。分離するのは「取込口と書き出し口」だけ。
- **判別は `Type` 列**: 取込時 `filterSentenceEngineImport(parsed)`（`lib/sentenceEngine.ts`・純関数）が `type` を見て `Structure`／`Message` の行だけを受理し、それ以外は `rejected` にカウントする。**Structure** は en/ja とも非空の当てはめ例文を1件以上持つ必要があり（無ければ rejected）、揃わない例文は捨てる。**Message** は `examples` を空配列に正規化する。`status` はユーザーがCSVで明示した値をそのまま尊重し補正しない。
- **取込＝マージ**（`useDeck.importSentenceEngine`）: `parsePhrasesFromFiles`（§6.3 と同じ .csv/.zip/.md 対応）→ `filterSentenceEngineImport` → `ensurePersisted` 後に `putPhrases`。**ID一致は上書き**、added/updated は既存ID集合との突き合わせで算出。SRS進捗は別ストアなので保持される。受理0件なら「Structure / Message の行が見つかりませんでした。Type列を確認してください。」を throw。
- **書き出し**: `phrasesToCsv(phrases.filter(isSentenceEngine))` を `shareOrDownloadCsv(csvFilename('sentence-engine'), …)` で（§6.6 の共有/保存フロー共通）。SEカード0枚ならボタン無効。
- **チャンクCSV書き出しからの除外**: 設定の「📤 デッキをCSVでバックアップ」は `phrasesToCsv(excludeSentenceEngine(phrases))` とし、構文・意味ノード教材を**チャンクCSVに混ぜない**（Notion往復を汚さないため）。フルバックアップ（`backup.ts`）は全件のまま。
- **内蔵デッキ66枚と更新導線**: `importBuiltinSentenceEngine`（`loadSentenceEngineSeed`→同じマージ）で内蔵デッキ（構文16・意味ノード50）を取込・**更新**できる。旧28枚版（構文16・意味ノード12）から50場面版への更新にも使える。空表示 `SeedDeckEmpty`（§16.3）も同関数に一本化。

### 16.7 意味ノード英語思考（`/think`・`pages/ThinkPractice.tsx`）
第3層 Message の**発展版**。用意されたカードを解く意味ノード生成（§16.3）と違い、**自分自身の思考**を素材に「日本語で完成文を作ってから訳す」癖を断つ。5ステップのウィザードで、AI（Gemma・§13.10）が分解と英文を2回添削し、成果を Message カードとしてデッキに残して再学習ループに乗せる。APIキー未設定時はページ側でゲート（チャット練習§8.13 と同じ案内）。今日のプラン（§15）には入れない。

- **フロー**:
  1. **思考の入力**: 伝えたいことを日本語で自由記述（会議で言いたかったこと・意見など）。
  2. **意味ノードに分解**: 「ラベル: 内容」の骨子を1行1ノード（2〜5行）で自分で書く。「🤖 AIに分解を見てもらう」で①分解評価（§13.10）→ 全体講評・ノードごとの ok/issue/fix・**AIの推奨分解**を表示。「この分解を採用」で textarea を推奨で置換できる（自分の分解のまま次へ進んでもよい）。
  3. **英文化**: 確定した意味ノードを常時表示し、1行1文（1ノード=1文）で自分で英作文。
  4. **AI英文チェック**: 「🤖 AIに英文を見てもらう」で②英文チェック（§13.10）→ 全体講評（良い点を先に）・文ごとの原文/指摘/**提案英文**（`suggestion`）/理由・「提案を採用」で自分の英文を置換・**使える表現 0〜3件**を「＋表現ストック」（`useStock.add`。追加済みは表示切替）。
  5. **保存**: 最終ノード（ja）と最終英文（en）をプレビューし「📦 意味ノードカードとして保存」。保存せず終了も可。
- **保存カード仕様**（`useDeck.addPhrases` で upsert）: `id=think-${stableId(ja全文)}`、`en`＝最終英文（改行 join）、`ja`＝最終ノード（改行 join）、`examples=[]`、`type='Message'`、`category`＝AIが返す場面名（`scene`。空なら「自分の思考」）、`level='Core'`、`priority='★★★★☆'`、`note=意味ノード英語思考で作成（YYYY-MM-DD）`、`status='進行中'`、`createdTime=new Date().toISOString()`。以後は意味ノード生成ドリル（§16.3）で出題され SRS に乗る。
- **学習ログ**: 英文チェック（Step4）を終えた1本を `think` イベント（`nodeCount`／`sentenceCount`／`savedCard`）として記録し、`noteChatComplete` と同じ `logAndMaybeStreak` 経由で**最低ライン達成**に数える（§14.1）。`sentenceCount` は `outputCount` に加算（§14.2）。記録は1セッション1回（保存時 `savedCard=true`／保存せず離脱時 `false`。多重計上を防ぐガードつき）。

## 17. 検索の検証と較正（`components/ReproCard.tsx` / `lib/kpi.ts` / `lib/chunkMatch.ts`）

自己採点は**答えを見た後**にしか押せない構造だった（`GradeButtons` は `revealed===true` でのみ描画）。
後知恵バイアスで「あー、知ってた」が `good` になり、`applyGrade` の `box+1` を通して**SRSの出題間隔に複利で乗る**。
さらにゴールの「次の一手」（§14.3）が「『できた』をあと N 回」＝**緑のボタンを押す回数**を目標に据えていた。
「思い出せた」と「知っていた」を分ける（学習OS化フェーズ3・要件 §4.28）。

### 17.1 検索コミットゲートと較正メーター【v1.7.0】
- `ReproCard` の `commitGate`（設定 `commitGate`・既定ON）: ONのとき**カード全体のタップでは開示しない**。
  「◯ 言えた／△ あやしい」の2択を押して初めて英文が出る。**申告と開示は1タップに統合**（操作回数を増やさない）。
- 申告は `onPredict` → 各ページの state → `useSession.answer(g, latencyMs, predicted)` → `useDeck.grade(...)` →
  `GradeEvent.predicted` として保存。**任意項目なのでDBマイグレーション不要**。
- `kpi.calibration(events)`（§14.2）が「◯と申告して実際に `good` だった率」と「△と申告して `good` だった率」を出す。
  設定「🎯 学習の精度」に横棒2本で表示。**母数10件未満は率を出さず件数のみ**（少数だと率がブレる）。
- 文言は責めない方向に倒す（「どうしても甘くなります（誰でもそうなります）」）。数字が悪くて凹むと継続を損なうため。
- 対象は `ReproCard` を使う4画面（今日の練習・瞬間英作文・構文ドリル・意味ノード生成）。**穴埋めは `ClozeCard` 経由なので対象外**。

### 17.2 声で答えるドリル【v1.9.0】
- 設定 `voiceAnswer`（既定OFF・`commitGate` がONかつ `speech.supported` のときのみ有効）で、申告2択を
  **英語の音声入力**（`useSpeechInput({ lang:'en-US' })`）に置き換える。**非対応環境では自動的に §17.1 の申告2択へ戻る**。
- **自動照合**（`lib/chunkMatch.ts`）:
  - `overlapRatio(expected, actual)` — 期待文の語が発話にどれだけ現れたか（0..1）。**多重集合**で数える（同じ語を2回言えば2回分）。
  - `matchLevel()` — `>=0.85` で `hit` / `>=0.5` で `partial` / それ未満は `miss`。
  - **完全一致（`matchesChunk`）を使わない理由**: 認識が1語取りこぼしただけで不一致になり、日本語なまりの英語では常態化するため。
  - **判定は参考表示のみ。減点・強制不合格には使わない**（「言えたのに不正解」が学習意欲を最も損なう）。miss の文言も
    「聞き取れた範囲では一致しませんでした」と断定を避ける。
- **発話開始の検出**: `useSpeechInput` の `interim` が初めて非空になった時点で `onLaunch` → `meter.launched()`（§16.4）。
  厳密な音響的オンセットではなく**認識エンジンの最初の部分結果**だが、タップ時刻より格段に妥当。
- **マイク開始前に `stopSpeaking()`** を呼ぶ。TTSの読み上げ音を自分のマイクが拾うため（TTSと認識は同時に使えない）。
- 記録: `GradeEvent.attempt`（認識テキスト＝証拠）／`autoMatch`（`hit`/`partial`/`miss`）／`launchMs`。
- `kpi.leniency(events)`（§14.2）＝**甘さ指数**（`miss` なのに `good` を付けた割合）。設定「🎯 学習の精度」に表示。
  誤認識も混じるため断定に使わない旨を添える。母数10件未満は非表示。
- 起動レイテンシ計測器を持つのは構文ドリル・意味ノード生成のみ。今日の練習・瞬間英作文は `attempt` / `autoMatch` は
  残すが `launchMs` は付かない。
